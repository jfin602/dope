# Work conversational session contract — approved 2026-11-24

Status: owner-approved forward design, amended by [c14 P1-R2 scope decision](../tasks/c14-work-redesign/scope-amendment-2026-11-24.md) and the [P2-R1 local Pi boundary](../tasks/c14-work-redesign/scope-amendment-2026-11-24-p2-r1.md); not product qualification.

For this correction, the persistent lifecycle applies to embedded local Pi New Work and WorkItem runs. Hosted Work retains its existing one-shot lifecycle and must be labeled so its controls and history make no persistent-session claim. Hosted conversational parity needs a separate runtime design and qualification; retain hosted selection and authorization. The interaction requirements below apply to persistent local Pi sessions unless they expressly describe legacy or hosted evidence.

Work is one persistent dockable session surface. New Work starts in editable setup (prompt, model, tool ceiling, sandbox). Start seals an immutable per-session execution contract and transforms the same surface into the live structured conversation. The full transcript remains accessible after completion, failure, stop, panel close and restart. Existing Select Work entries reopen their actual run histories; missing legacy events are explicitly labeled unavailable, never fabricated.

## Interaction
- During Running, composer submissions persist immediately as Queued and are delivered FIFO at the next safe agent boundary. Acknowledgment changes Queued to Delivered only after actual runtime receipt. Retry/restart must be idempotent; no duplicate worker or message injection.
- A Running message may wait until the current Pi turn and brokered operations settle. Dope does not expose Interrupt/Pause/Resume in this correction. Stop terminates active execution without erasing evidence. Finish explicitly freezes the candidate, runs Dope validation and enters guarded review.
- Completed sessions accept follow-up turns with original maximum grants, model and sandbox; Fork creates a separately reviewed new setup. No silent permission expansion.
- Preserve typed tool invocations, agent responses, approvals, errors, diagnostics, checkpoints, candidate review and evidence receipts. Do not misrepresent tool activity as conversational prose.

## Presentation and authority
Use shared safe Chat Markdown/scroll/composer primitives but separate Chat identity and authority from Work AgentRun, ExecutionGrant and broker. Compact locked configuration disclosure remains inspectable. Work can dock left/right/bottom/center and maximize within existing Theia layout; no second center-only transcript owner. Retire legacy center AgentRun transcript only after parity verification; no hidden fallback. Editor/preview/Roadmap stay available.

## Qualification
T1 lifecycle/queue/Finish/Stop and UI tests; T2 persistence, recovery, post-review follow-up, old-run compatibility, grants, candidate validation and Roadmap evidence; T3 independent connected browser with live tool calls, queued messages, Finish/Stop, restart, history and docking. Record exact-source evidence and gaps. Docs approval alone does not implement, Run, award Gate GREEN or change version.

## Forward amendment — 2026-11-25: one Work conversation, multiple Pi sessions

This forward design supersedes the 2026-11-24 requirement that a completed Work session continue only with its exact original model and maximum grant or use Fork for a new setup. It does not alter the historical c14 implementation or qualification. The current product supports persistent local Pi Work; hosted Work remains visibly one-shot until separately designed and qualified.

**Identity.** A Dope Work session is the persistent dockable conversation. It contains ordered, immutable Pi execution segments. Each segment starts a fresh Pi SDK session and owns its AgentRun, prompt, model/grant/sandbox facts, candidate, typed tool transcript, final message and terminal outcome. A running Pi session may accept queued turns until it ends. The next segment does not need the same live Pi process, in-memory context or model. The earlier segment's status and evidence never change because a later attempt succeeds.

**Composer and transcript.** While a segment is running, Send queues a message to it, FIFO after the current turn and brokered operations settle; mark Delivered only on exact acknowledgment. After a completed, failed, stopped or interrupted segment, the same bottom composer accepts a new prompt and starts a fresh Pi segment directly below the preserved transcript. Render all segments as one continuous Chat-style conversation: right-aligned request bubbles, collapsible activity expanded by default, left-aligned answers with the shared footer, and no segment divider. Put status and elapsed time in the activity row; keep run IDs and provenance in Run Details below the composer. Show a red final system answer for failure or cancellation when needed, including cancellation after earlier agent replies. The composer must indicate whether Send queues or starts a new segment. An ordinary failure with verified no tool effect needs no Fork, separate recovery screen or Chat navigation. Keep keyboard, narrow dock and scroll behavior usable; never fabricate missing legacy transcript events.

**Context and authority.** Give the fresh Pi session the new prompt plus a bounded, source-labeled account of saved prior segments. Distinguish developer messages, actual tool outcomes, validation and candidate decisions from unverified model claims. Keep the full transcript in Dope even if the new model receives only an excerpt. Recheck project/worktree, current source basis, task scope, model eligibility, selected tools, sandbox and ExecutionGrant/broker authority for the new segment. A different model or permission set may be reviewed inline at Send; never silently expand authority or force an exact old model. Required grant, source or candidate decisions stay in the same Work conversation. Resolve an outstanding candidate review before relying on its effects; no automatic promotion, Work completion or Roadmap progress follows from another prompt.

**Uncertainty.** A denied no-effect tool call can be followed by a new prompt directly. If a crash leaves message delivery or tool/candidate effects uncertain, show the specific uncertainty inline and require verified reconciliation before starting another segment. Restore only verified saved candidate bytes; otherwise disclose and discard uncertain effects. Never replay an in-flight message or tool call automatically, and never describe a fresh Pi session as restored in-memory Pi state. Fork remains optional only when the developer wants a separate Dope Work conversation or task lineage.

**Qualification.** Check active queue versus terminal Send, ordered immutable segment transcripts without a divider, bounded context provenance, model/grant/source changes, candidate decisions, no-effect denial versus uncertain restart, idempotence, old-run history, keyboard/narrow docking and real local Pi browser behavior. Report native and hosted limits separately. Documentation approval does not implement this amendment, Run Work, award Gate GREEN or change version.
