## Goal

Make the Roadmap the project's entry and monitoring center: developer plans Phases and Gates; explicitly finishes planning for one Phase; reviews/starts existing Work under existing grant safety; Work validates actual source; verifiable receipts become attached to Criteria; Gate/Phase qualification is derived and auditable; a separate owner closeout completes the Phase. No redundant completion checklist.

## Sequence

1. Establish per-Phase coverage-checked planning lock with durable exact revision basis.
2. Bind locked Phase requirements to existing Planning Bridge WorkItems and reviewed Work launch.
3. Display planning lock and safe Work navigation on Roadmap canvas.
4. Ingest provenance-bearing Work/validation evidence through the existing Gate evidence boundary.
5. Reconcile criteria/gates and Phase eligibility from current verified evidence.
6. Handle source drift, reviewed amendments, history and restart with affected-only invalidation.
7. Show live Work progress, evidence, failures and next actions in the Roadmap without duplicate authority.
8. Run source-bound integration, adversarial permission and finally independent manual browser/native owner qualification.

Each ordinary implementation checkpoint is narrowly bounded (target <=8 minutes; hard stop 15 minutes), with a distinct T2 integration and last T3/manual closeout. No model inference auto-grants authority, no new second source store, and no false GREEN. Explicit later owner execution of the authored runner stack is the Run authority; baseline and docs writing are not that run.
