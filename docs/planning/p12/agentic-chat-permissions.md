## Scope and ownership
Pi must retain its tool-selecting, iterative coding-agent capabilities in Chat, Planning and Work. Dope owns the one saved ChatPanel, project root/identity, AI Center selection, permissions, Roadmap and linked Markdown, Work grants, candidate review, durable History and approvals. Do not build a second Chat, Work or agent loop or treat Pi's session as canonical state.

Native tower-defense testing found ordinary Chat could not autonomously inspect its project without manually supplied source. This is a defect in the *integration policy*: current no-tools Chat mode aborts Pi tool calls. Pi-selected eligible project file discovery, search and reading must work without attachments. This does not authorize Dope to preload full source-file bodies. Manual attachments are optional emphasis; "every file" is subject to project ownership, protected paths, credential and isolation rules, not full host filesystem access.

## Pi-only source context — 2026-10-31 approved forward contract

**Current implementation (not Pi-only):** The backend calls `ChatProjectGrounder.ground(root, content)` before Pi execution. `ChatContextComposer` places `[Auto ...]` file bodies in the model request. A fresh read-only [Qwen3.5-9B control](../tasks/c12-planning-recovery/qualification/2026-10-31-p1-r2-loop-context-isolation.md) received the exact source bytes automatically and answered correctly with zero Pi file tool calls. That is a Dope automatic source read, **not** a Pi autonomous read.

**Target for Pi-backed Chat:** Provide compact workspace/project identity, active project-relative file path and selection-location metadata where available, and concise relevant typed artifact references/capabilities. Let Pi choose the safe Dope-brokered read/list/search tools when it needs file contents. Do not automatically inject entire active or related source files, cached excerpts, directory-wide source bodies or fallback hidden reads. Explicit user attachments, deliberately shared selected code, current user text, completed conversation pairs and selected typed Roadmap/Planning context stay intentional inputs, not automatic source discovery. An explicit no-tools request must not trigger a covert project source read.

**Compatibility, security and provenance:** Scope the removal to eligible Pi Chat; preserve non-Pi provider context behavior unless separately reviewed. Preserve Dope's source/path/symlink/secret protection, read limits, tool call limits, command Ask/Allow policy, retry/source freshness, context budgeting and exact model/provider selection. Track a supplied reference or file byte sequence distinctly from an observed Pi tool read, with tool invocation/result and source identity/hash. A Dope auto-context hash alone cannot pass a Pi-read qualification gate.

**Required qualification:** In a fresh Pi Chat with no attached fixture, confirm the initial assembled request contains path/metadata but no `src/counter.js` body. Observe an actual Pi-brokered read with matching bytes/hash and a complete, grounded final answer. Test no-tools opt-out, explicit attachments/selections, typed Roadmap content, non-Pi compatibility, read-only denials, retries, cancellation and output-limit recovery. Retain [Qwen30 scoped P1 GREEN](../tasks/c12-planning-recovery/qualification/2026-10-31-p1-final-qwen30.md) and [Qwen3.5-9B P1-R2 NOT GREEN](../tasks/c12-planning-recovery/qualification/2026-10-31-p1-r2-loop-context-isolation.md) as separate, unchanged evidence. ## Composer — Commands: Ask / Allow
The composer is a stable input surface: message field, existing actions, model selector, Commands Ask/Allow and send/cancel control. Its height stays fixed as draft text grows; the message field scrolls internally. Its layout must not expand or change for tool progress, planning state, context, warnings, approvals, proposal previews, errors, recovery notices or other announcements. Show every such notice and interactive review in the scrollable Chat response area, associated with the relevant turn where available. This applies to browser and native ChatPanel, including pending command approval and plan acceptance. The composer action menu is user-invoked and does not carry announcements.
Model selection errors appear there as a red error card with an obvious **Open AI Center** action that opens the relevant role or connection settings. Never place the error above the Chat header.
Local tool verification errors use **Open tool verification** to open AI Center at the exact selected connection and model's **Verify Coding Agent tools** control; the link does not start a verification or retry the Chat turn by itself.
The recovery action remains on the saved failed response after reopening the Chat.

Use a compact visible two-option control beside model selection in the **existing composer**:
- **Ask** (default): Pi may list/read/search eligible project files automatically. Before a command execution, pause the Pi agent and show its exact command, project/cwd, sandbox scope and effect summary. Developer may **Allow once** or **Deny**; no command executes while pending. One-use approval binds Chat + project + current turn + exact command digest + canonical root/source basis + expiry. Cancel, change, stale, wrong owner or reuse denies.
- **Allow**: Pi may run sandbox-*eligible* investigation or test commands without asking each time, with observable activity. This does NOT confer arbitrary host shell, secrets, network, outside-root access, canonical writes, Git mutation, automatic Work or Roadmap publication. Unsafe commands deny regardless of toggle.
- Mode is scoped to one Chat/project/active app session. A new Chat starts Ask; switching project or restarting app resets Ask; another Chat cannot inherit this Chat's Allow. Persist audit results, never a reusable authority token.
- Reads, listings and text/path searches do not require approval. Stream compact expandable tool activity without contaminating copied AI response or transcript with debug/secret metadata. Preserve drag-to-scroll, selection/copy and cancellation.

## Pi agent tool bridge
Use Pi's actual custom-tool/multi-step agent loop through the existing pinned worker and Dope host. Expose brokered read/list/path search/text search backed by ChatProjectGrounder's current safe realpath/symlink checks, content limits, source hashes and evidence. Chat/Planning tools are read-only or sandboxed commands; do not expose Pi built-in unrestricted read/write/bash tools in the host process. Pi makes tool-selection decisions, Dope enforces effects. Cap input/output/tool calls and accurately report truncation/omissions; no silent provider fallback.

Command execution must have an OS-enforced project-read-only sandbox, ephemeral temporary writes, sterile env, inaccessible private home and credential mounts, no network sockets (namespace/seccomp), limited process/CPU/time/output. A command's apparent read-only wording is not an access control; never run a model-chosen command in the unsandboxed Dope backend shell. Fail closed when sandbox is unavailable. Allow should not be made useless by an artificially tiny test/build-only command list, but cannot weaken OS protection.

Planning uses the same investigation tools while preserving typed proposals, Roadmap revision/provenance validation and explicit approval to publish. G3 deterministic response-first/no-action routes must not introduce a gratuitous second inference. Chat can **prepare an existing Work draft** for review, but cannot execute Work, directly edit canonical files through model tools, or approve promotion. The separately scoped ADR 0041 documentation action below permits only an explicitly reviewed Dope-owned application. Work retains current candidate workspace, grants, tests, Accept/Reject and History. Preserve provider independence, exact model and local-only settings.

## Reviewed documentation application — separate ADR 0041 scope

The existing ChatPanel may prepare a bounded documentation proposal, show its rationale and concrete diffs, and invoke the Dope-owned application action after developer approval of that exact change set. Bind approval to project/worktree identity, eligible targets, reviewed source versions and actual changes; reject stale or changed proposals until reviewed again. Use existing ordinary editor/diff surfaces. One coherent reviewed set needs one approval, not repetitive per-file approval.

This is not a Pi file-write/shell tool or an effect of Commands Allow. General command investigation keeps its project-read-only sandbox. Linked Roadmap edits route through its existing authoritative source owner; no separate Markdown writer, automatic Work Run, architecture adoption or Gate qualification follows. Application records and recovery evidence belong to the documentation owner; only verified actual applied effects appear as documentation-change History. Review, proposal, approval alone, rejected/cancelled-without-effects, no-op and failed-with-no-change attempts do not.

When applicable, offer lightweight document/section pointers through existing Chat/Work facilities and let the selected agent choose authorized reads and handle their content in its own context. No automatic document-body prefill, per-call corpus scanning, auxiliary selector/summarizer inference or repeated notice injection follows from this feature. Explicit documentation review still reads the target sources needed for a concrete proposal. Offered references, observed reads and demonstrated requirement-following are distinct; no pointer or read alone binds every document statement into a task. Recheck only a materially changed accepted task basis, preserving active/completed snapshots and selected provider/local policy. Missing retrieval capability must be reported or narrowly repaired through the approved boundary, never bypassed with unrestricted tools or bulk preloading. Detailed recovery, History, retrieval and performance gates belong to the [documentation workflow contract](documentation-workflow-contract.md), not the older P1–P5 correction's qualification claim.

## Qualification
Real source-bound browser and owner-operated installed Electron must show: tower-defense code exploration with no file attachment; actual Pi read/search events with verified file references and grounded milestone; Ask deny/approve-once, Allow eligible command; sandbox denial of writes, network, secrets, outside-root, symlink escape; Planning review without automatic mutation; cancellation/restart/project-switch permission reset; preserved Chat copy, continuity, provider choices and prior Work success. Browser and native evidence independent. Old P12 P1–P8 and B1–B9 results remain historical; this contract does not grant new Green, Run or a version change.
