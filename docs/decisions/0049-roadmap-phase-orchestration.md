# ADR 0049 — Controller-owned incremental Roadmap generation

**Owner decision:** 2026-11-03 (America/Chicago). **Status:** APPROVED FORWARD ARCHITECTURE / DOCUMENTATION ONLY. **Implementation:** [c12-rm-orch](../tasks/c12-rm-orch/README.md). **Contract:** [Roadmap phase orchestration](../planning/p12/roadmap-phase-orchestration-contract.md). **Baseline:** Dope 0.12.7 as documented; the owner's actual local HEAD and dirty tree must be verified before execution.

## Context and decision

Qwen3.5-9B has demonstrated useful project-aware conversation and bounded individual Roadmap edits. In contrast, full-Roadmap freeform text extraction was inconsistent, strict whole-Roadmap JSON/RM1 requirements caused model stalls or incomplete results, and natural-plan-then-conversion introduced a second sequential inference. Earlier natural plans could be useful, but their output was not a dependable machine-readable canonical structure. These observations motivate a change of architecture, not a guarantee that an incremental approach is already qualified.

**Decision:** Dope provides exactly **one first-class greenfield Roadmap Generation Controller**. It owns one project-bound execution session, chosen model/provider, context budget, serial calls, bounded scope ledger, validation, noncanonical staging, progress events, cancel/failure/continuation states, and final review. It asks the selected model for **one Phase at a time** using existing native, bounded Roadmap edit/stage capabilities; for a Phase needing multiple small operations it coordinates those serially. The model proposes content, not format, source identity, approval or qualification. Dope assigns IDs, parent relationships and trusted revision/source/lease basis. A validated Phase/Gate/Criterion is staged under **one existing noncanonical proposal authority** and projected live in the Roadmap canvas. Only explicit owner Apply changes the canonical index and linked Markdown.

## Invocation — exact user slash command only

The **sole executable entry** to the Roadmap Generation Controller is a **trusted user-authored Chat submission** starting with the exact leading command `/gen-roadmap <roadmap prompt>`. Parse at the Chat command boundary **before any Pi inference**; after normalizing outer composer whitespace, require the exact `/gen-roadmap` token, a whitespace separator and a nonempty trimmed prompt (multiline body allowed). Strip the token before passing the body to the controller, retain trusted user-command provenance, and show usage with **zero controller/inference/stage/write calls** for missing body. Never scan quoted/code/prose content or model/tool output for executable commands. No intent classifier or natural-language routing, no automatic greenfield or Planning invocation, no `/roadmap` or `/roadmap generate` alias, no direct Generate Roadmap button, Work, injected tool/model text, old-format fallback or replay invocation. A retained UI affordance may only prefill the command for the user to submit. Normal Chat/Planning and ordinary `/roadmap` editing are unaffected. The command conveys requested intent, **not** permission to bypass Ask/Allow, project/source/revision/lease checks or final owner Apply.

## Clean cutover — no compatibility generation routes

Retire from executable greenfield generation: (1) response-first freeform-to-Roadmap parsing; (2) monolithic freeform/Markdown or typed whole-Roadmap generation; (3) full-plan JSON envelope generation; (4) Roadmap Markers v1 (`RM1`/`END`) model generation and parsing; (5) the locked natural plan followed by automatic RM1 conversion; (6) model-managed default multi-batch greenfield staging orchestration; and (7) fallback switches, flags, prompts, dispatch branches, obsolete test-only implementations and UI states that keep any of these reachable. No backward-compatibility shim, fallback parser, silent retry through an old format, or second writer/store. Historical reports, authored prompts, snapshots, and already accepted Roadmaps are **not** deleted or rewritten.

Preserve as genuine shared infrastructure, after source inspection: schema-2 RoadmapStore/Service and ProjectPlanningActions, Pi native broker/permissions, source/revision/lease checks, validated typed staging/proposal transactions (including `RoadmapNativeStageOwner` and `stageTypedRoadmapDraft` only insofar as they are general checked owners), saved Chat continuity, canvas editing/granular review, linked Markdown safe sync, append-only History/restoration, existing imported/indexed data, and evidence/coverage/qualification authority. Prune generator-specific helpers from these owners; do not rename dead legacy generators and retain them.

## Behavior and truth

- A single controller owns each session and advances **sequentially** only on a validated result. Never assume a model emits one huge deterministic outline; no whole-plan serialization contract. A bounded per-Phase native operation can create a Phase and associated Gates/Criteria; if necessary, use small Gate edits in the same Phase transaction flow.
- Model output and tool arguments remain untrusted. Dope checks required Phase title/objective, Gate title/purpose, at least one observable Criterion where required, consistent parent IDs, duplicates, bounds, source/revision/lease, and staged operation dependencies. Malformed results do not advance. No model self-Apply or generic source-write authority.
- Project scope tracking records explicit requested requirements, staged coverage candidates, unresolved questions/omissions and generation bounds. Structural checks are deterministic; semantic coverage suggestions from a model are **not** proof of completeness. The final review must expose uncovered or uncertain requirements and not silently claim total project coverage.
- The same validated provisional projection feeds the existing canvas in live, asynchronous/coalescible updates. It must never slow generation/tool completion, steal focus, repeatedly recenter, or alter accepted/qualified state. Show actual counts and `Generating/Incomplete/Ready/Failed/Cancelled/Stale`; separate provider reasoning when available from structural progress when unavailable.
- Active-tab-only auto-preview, manual View in Roadmap, owner camera/focus, cancellation, stage expiry and historical-mode protections remain. No speculative percentage or AI-generated GREEN. Interrupted drafts are inspectable but not applicable until freshly validated and dependency-closed for owner review.
- Preserve strict /roadmap editing and explicit /gen-roadmap generation permissions, Ask/Allow and project/root/chat/turn/model/source isolation; no automatic provider switch, no mutation of qualification/evidence/waiver, no canonical/Markdown/applied-History writes before explicit Apply.
- Bound phases, calls per Phase, retries, tokens, wall-clock and stalled runs; stop with useful partial draft. Performance must be **measured**, including time-to-first-validated-Phase and time-to-reviewable-draft, not promised.

These are no longer run routes; their implementation history, NOT GREEN results and safety evidence remain immutable. Do not use future default-generation instructions in ADR 0047 to override this decision.
