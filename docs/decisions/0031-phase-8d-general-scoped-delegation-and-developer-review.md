## Context and decision

8A–8C qualified Codex reference agent execution, isolated CandidateDelta promotion and Dope-owned Prompt Stacks. The real Adaptive SEO Prompt Stack and c8-work-mode subsequently qualified Green at unchanged 0.8.20. The owner activated 8D on 2026-10-09 to generalize that substrate to Planning WorkItems without creating competing execution authority.

1. **Identity and lifecycle.** Planning owns WorkItem intent and revision; AgentTask is the bounded execution primitive. A developer may explicitly derive one or more AgentTasks from a WorkItem. Persist Dope-owned project/map/WorkItem origin and immutable derivation snapshot on AgentTask; inverse WorkItem task lists are derived from AgentStore rather than duplicating mutable links in both stores. A successful AgentRun is not WorkItem completion. Direct Work/Prompt Stack tasks never need a manufactured WorkItem.
2. **Scoped ownership.** WorkItem assignment is HUMAN, AI or SHARED. Human-only portions cannot be delegated. SHARED records a bounded delegable working set and human-reserved responsibility. Ownership can *narrow* an approved ExecutionGrant but never expand it. Enforce these constraints on both task creation and authoritative promotion.
3. **Review policy.** WorkItem-origin tasks use a review-required promotion policy, preserving direct/Prompt Stack pre-existing already-granted promotion semantics. Freeze CandidateDelta, execute required Dope-owned validation against the exact frozen basis, then hold before authoritative promotion. Show actual candidate diff, validation, changed paths and scope. Accept/reject is an explicit persisted developer decision. Acceptance rechecks frozen candidate identity, authoritative Git/path basis, grant, delegated scope and validation immediately before Dope-owned Authority/ToolExecutor promotion. Rejection applies nothing; both decisions are idempotent and restart-inspectable. A WorkItem completes only through a separate explicit developer transition.
4. **ProposedAction.** Record consequential, out-of-grant or human-reserved requests with origin, effect target, required authority and decision lifecycle. Existing routine in-grant create/modify does not require an extra ProposedAction per file. The fixed initial 8B profile still denies delete/rename, Git writes/history, network, secrets, private state, outside-root and system actions. Developer review is not sufficient to enable an unenforceable new effect class; do not introduce implicit escalation or model self-approval. Grant expansion, if later required, needs separate accepted policy and security qualification.
5. **Steering.** Developer steering is a typed, revisioned, persisted intent and observable acknowledgement, not hidden chat text. Changes take effect only at a safe boundary supported by current runtime/adapter. If a live Codex turn cannot be steered, report queued/unsupported and offer deliberate stop/restart/new task without silent rerun, grant change or mutation of a frozen/reviewed candidate. Preserve cancellation behavior and historical run truth.
6. **Map impact.** Once Dope applies a candidate, associate changed paths and accepted source-evidence fingerprints with affected current Software Map/Planning IDs where deterministically resolvable. Mark bounded stale/re-analysis-needed evidence, preserve unknown/unresolved impact honestly and expose developer-invoked targeted re-analysis. Do not silently edit canonical architecture or implement Phase 10 continuous background alignment.
7. **Persistence and layering.** Visual Planning state remains at `.dope/planning-maps.json`; AgentTask/AgentRun/review/steering/action state remains at `.dope/agent/`. Typed services link stable IDs with project identity, revision/basis checks, optimistic concurrency, idempotent recovery and safe cross-store partial-failure reconciliation; never promise an implicit cross-store transaction. Domain remains independent of Theia and provider-native schema.
8. **Presentation.** Work remains separate from Chat. Extend Planning WorkItem and Work detail with delegation, ownership, steering, candidate diff, review, consequential actions and validation while reusing the qualified transcript and panel machinery. Close/relocate/select actions cannot themselves mutate task authority or cancel an execution.

## Gate and deferred work

Prove two WorkItem-derived tasks, HUMAN/AI/SHARED boundaries, candidate accept/reject and failed validation/denied effects, steering truth, stale-basis/restart/idempotency, affected-map staleness and legacy direct/Prompt Stack non-regression using real Codex/Dope GUI evidence. Qualification details: `docs/stability-contract.md`; execution plan: `docs/planning/p8/phase-8d-plan.md`.

Do not introduce arbitrary partial-file promotion, automatic self-escalation, multi-agent swarms, 8E local-model parity, Phase 9 DevelopmentSession or Phase 10 background alignment **inside Phase 8D**. The original owner activation was not a Green claim; the separate later c8-fix qualification established the 8D Green claim.
