KNOWN FAILURE

Preserve the demonstrated fact: the controlled P4 run made twelve model calls while only eleven call records remained visible, and the first Gemini attempt failed with a sanitized transport/type error before a manual retry.

ATTEMPT LEDGER

Introduce the smallest Dope-owned provider-independent attempt record that can retain, for every actual call:
- stable logical-call and attempt identity;
- stage/call purpose and subject;
- provider kind and model label;
- attempt number / retry relationship;
- wall-clock duration;
- request/output bytes;
- input/output/total tokens and measurement source when available;
- safe failure classification;
- cache/reuse state where applicable;
- whether the attempt's output was consumed.

The attempt ledger is derived operational state, not canonical project state.

Progress events may project from the ledger but cannot be the only retention path. A failed attempt must remain inspectable after a later attempt succeeds.

Do not retain credentials, raw secret-bearing provider errors or request content merely to satisfy telemetry.

BOUNDED RETRY

Add an explicit retry classifier/policy for transient Gemini failures only.

Eligible examples may include sanitized transport/type failures and upstream 5xx/unavailable failures when the adapter can classify them safely.

Retry requirements:
- same exact stage request;
- same provider;
- same selected model;
- capped attempts;
- visible attempt relationship/status;
- no hidden provider/model fallback;
- cancellation remains cancellation.

Do not automatically retry:
- invalid stage JSON;
- schema/contract failures;
- fabricated/invalid evidence refs;
- architecture/content rejection;
- authentication/configuration failures;
- deterministic planner/input failures.

Do not weaken provider-independent contracts to accommodate Gemini.

TESTS

Install focused permanent regressions proving:
- failed first attempt + successful retry leaves both attempt records;
- successful single attempt leaves exactly one consumed record;
- retry cap is enforced;
- non-retryable invalid JSON/schema/content failures are not retried;
- provider/model/request identity does not change across retry;
- sanitized failures contain no secret/raw request leakage;
- progress projection does not erase attempt history.

Use existing provider/orchestration test files unless a small dedicated test is clearer; wire any new test file into `test:product`.
