GOAL

Make automatic attempt retries visibly distinct from terminal analysis failure, color and label stage states, and couple manual failed-stage retry to the selected tested model.

PREFLIGHT

Read BOOT.md, AGENTS.md, ADR 0012/0013/0014/0016, docs/workflow.md, this correction README/assessment/plan, and current synthesis/UI source/tests. Trace callers of `SynthesisStageCache.run()`, progress event parsing, `retryFailedStage()`, model selection/probing and `SoftwareMapWidget.renderProgress()` before editing.

IMPLEMENTATION

- In `packages/software-map/src/reconciliation.ts`, determine whether an attempt will be retried before reporting it to progress consumers. Show each failed attempt in the ledger, but report `retrying` when another automatic attempt will follow. Emit the next attempt's start/number. Do not claim a fixed total unless known.
- Align retry classification with ADR 0014: classified transient Gemini failures remain bounded; one malformed structured-output result may retry once; architecture/content invalidity is terminal. If malformed output cannot be distinguished safely, fail closed to manual retry. Preserve same request/model and no provider fallback.
- Make `software-map-widget.ts` use backend run state for the terminal heading. Show safe reason, current stage/subject/model, retry attempt and recovery, then terminal failure only when stopped. Give completed/current/queued/failed list items semantic theme-token colors plus text labels; maintain contrast and keyboard readability in alternate themes. Do not show raw provider errors, prompts, keys or hidden reasoning.
- Place **Retry failed stage with [selected model]** beside the relevant model selector. A changed Gemini model must pass `probeGemini()` before retry enables. Keep **Restart analysis** distinct and preserve saved checkpoint provenance.
- Reuse existing controller/backend/cache state; do not add parallel progress persistence or a dependency.

TESTS / VALIDATION

Add the smallest permanent focused regressions for transient and malformed automatic retry, architecture/content non-retry, terminal exhaustion, successful recovery, changed-model probe gate, saved checkpoint reuse/provenance, alternate-theme semantic selectors and sanitized messages. Run affected synthesis/UI tests and required affected build/typecheck only, then `git diff --check` and unchanged-version/no-root-lock checks. Do not run `npm run check`, live provider comparison, packaging or broad restart suites.
