SOURCE FACTS TO CORRECT

The current architecture has these concrete leaks:
- shared System/Subsystem/Component synthesis instructions live in `lmstudio-synthesis-provider.ts`;
- Gemini imports those semantic instructions from the LM Studio adapter;
- `SoftwareMapBackend` keeps concrete `localProvider` / `geminiProvider` lifecycle state and branches refresh/select/probe/ready/warm-up/error behavior by provider;
- `HierarchicalSynthesisOrchestrator` receives a Local-only `beforeFirstCall` warm-up callback from the backend;
- `SynthesisStageCache` hard-codes automatic retry around `provider.kind === 'gemini'`;
- provider-specific setup/credentials are genuinely different and MAY remain explicit.

IMPLEMENTATION

A. ADD THE MINIMAL GENERAL MODEL RUNTIME CONTRACT

Use the existing provider/Theia-independent `@dope/contracts` package. Do NOT create a new package merely for ceremony.

Add a compact Model Runtime/session contract that contains no Software Map concepts.

It must cover the real current needs:
- provider/runtime identity;
- model discovery;
- selected-model state/selection;
- probe/readiness;
- model/runtime capabilities including context/input capacity and token-estimate quality;
- conservative token estimation;
- optional pre-real-work warm-up;
- structured JSON generation using a caller-supplied system instruction, input/user content, JSON schema and schema name;
- normalized usage;
- normalized safe failure classes;
- a provider-neutral bounded retry decision/policy sufficient to preserve current behavior;
- cancellation where the existing provider already supports it.

Do not add chat history, Agent Mind, tools, sessions, mutation authority, OpenAI/Codex behavior or other Phase 7 product concepts.

Keep the contract capability-based rather than encoding `local` / `gemini` as the entire future provider universe.

B. MOVE SMAP SEMANTICS OUT OF LM STUDIO

Create a provider-neutral Software Map synthesis-strategy module.

Move current shared semantics there:
- compact rules;
- System Discovery;
- System Challenge;
- Subsystem Discovery;
- Subsystem Challenge;
- Component Discovery;
- reconciliation;
- verification;
- targeted refinement;
- stage/refinement schema and schema-name selection.

The strategy may expose one typed function/spec that maps a current stage/refinement request to:
- instruction;
- strict Dope-owned schema;
- schema/output name.

Keep existing instructions materially unchanged in this correction unless moving them exposes a mechanical defect.

Hard rule:
- Gemini runtime must not import LM Studio runtime;
- LM Studio/Gemini runtime adapters must not own System/Subsystem/Component synthesis instructions.

Do NOT implement separate Local versus hosted prompts yet. ADR 0022 permits that later; this correction only creates the seam.

C. MAKE ONE GENERIC RUNTIME-BACKED SMAP PROVIDER

Create one provider-neutral adapter that combines:
- a Model Runtime/session;
- the current sMap provenance provider kind needed by retained synthesis work (`local` / `gemini`);
- the Software Map synthesis strategy.

It should satisfy the existing `SynthesisProvider` contract consumed by evidence planning, cache and hierarchy orchestration.

Responsibilities:
- derive current `SynthesisCapabilities` from runtime capabilities while preserving existing reserve/input-budget behavior;
- serialize the stage/refinement request;
- apply `assertSynthesisInputBudget`;
- obtain instruction/schema/name from the sMap strategy;
- call generic structured generation;
- translate normalized runtime usage into existing `SynthesisStageUsage`;
- translate normalized runtime failure into the existing safe synthesis failure boundary;
- expose generic readiness/pre-evidence warm-up;
- expose provider-neutral retry policy.

Do not make the generic adapter inspect LM Studio or Gemini native response shapes.

D. REFACTOR LM STUDIO TO RUNTIME / TRANSPORT ONLY

Preserve current Local behavior:
- endpoint normalization and optional token;
- model discovery and explicit selection;
- Qwen preferred ordering helper if still needed by setup UI;
- configured context capacity validation;
- probe with synthetic non-project structured output;
- warm-state invalidation on reconnect/model change/error;
- immediate pre-real-work warm-up with no project evidence;
- OpenAI-compatible structured-output transport;
- conservative token estimate;
- provider-reported usage when present, estimated input usage otherwise;
- safe timeout/network/HTTP/refusal/JSON failures.

The adapter should accept caller-supplied instruction/schema/input for real generation. It must no longer know what System Discovery or Component Discovery means.

Do not make Local automatically inherit Gemini retry semantics.

E. REFACTOR GEMINI TO RUNTIME / TRANSPORT ONLY

Preserve current Gemini behavior:
- AI Studio API key boundary and sanitization;
- model discovery/filtering/selection;
- model metadata/context capacity;
- Gemini JSON-schema projection;
- synthetic readiness probe;
- structured generation;
- usage metadata;
- cancellation/timeout;
- current bounded automatic retry behavior for transient transport/upstream and the currently allowed invalid-JSON retry, but express the decision through provider-neutral runtime/provider policy rather than `provider.kind === 'gemini'`.

Gemini must receive sMap instructions/schema from the generic runtime-backed provider/strategy.

Never expose the API key or raw provider text in errors/progress/cache identity.

F. CLEAN SOFTWARE MAP BACKEND LIFECYCLE OWNERSHIP

Provider-specific CONFIGURATION may remain explicit:
- Local endpoint/token/context settings;
- Gemini credential lookup/storage/API-key construction;
- explicit provider choice/disclosure.

After configuration, ordinary lifecycle must use one active generic runtime/session:
- refresh discovered models;
- select model;
- probe;
- ready state;
- capabilities;
- warm-up/pre-evidence preparation.

Remove concrete `localProvider` / `geminiProvider` lifecycle branching where that generic session now covers it.

Keep direct test injection of a `SynthesisProvider` only if it remains the smallest clean test seam; do not preserve obsolete production coupling for tests.

No silent Local <-> Gemini fallback.

G. REMOVE PROVIDER-NAME LOGIC FROM ORDINARY ORCHESTRATION

In `HierarchicalSynthesisOrchestrator`:
- replace the backend-supplied Local-only first-call warm-up callback with a provider-neutral synthesis/provider hook such as pre-evidence preparation;
- preserve the rule that project evidence is not sent before required readiness/warm-up succeeds;
- preserve progress event semantics including `model-warm-up`.

In `SynthesisStageCache`:
- remove hard-coded `provider.kind === 'gemini'` retry selection;
- ask the generic provider/runtime policy whether the normalized failure/attempt is retryable;
- preserve the existing bounded Gemini attempt behavior and Local behavior;
- keep attempt ledger/checkpoint/provenance semantics unchanged.

In backend failure handling:
- keep sMap validation/domain errors specific;
- otherwise surface only normalized safe provider/runtime errors;
- do not branch on provider names merely to sanitize errors.

H. PRESERVE CURRENT PERSISTED / PRODUCT CONTRACTS

Do not redesign persisted sMap analysis/checkpoint state just to generalize the runtime.

Current persisted provenance may continue recording `local` / `gemini` for these existing sMap providers.

Do not change:
- ArchitectureEvidencePacket;
- SynthesisStageRequest / result schema versions;
- ArchitectureProposal schema;
- deterministic evidence planner semantics;
- checkpoint reuse identity;
- review draft persistence;
- canonical architecture;
- Flow;
- Planning Maps.

Do not add an OpenAI provider in this correction.

PERMANENT REGRESSION COVERAGE

Update/add focused tests proving:
1. shared sMap instructions/specs are provider-neutral and both current providers receive them through the generic adapter;
2. Gemini code does not import LM Studio code for synthesis semantics;
3. concrete runtime adapters contain no System/Subsystem/Component strategy constants;
4. Local probe + warm-up occur before first real project-evidence generation, with synthetic requests containing no repository packet data;

10. Local/Gemini errors remain sanitized and no secret appears;

12. targeted Search Deeper/refinement uses the same strategy/runtime seam.

Add one cheap architecture guard that is narrow enough to permit legitimate provider-specific setup/credential code but catches reintroduction of semantic ownership/cross-provider imports.
