# Ordinary Chat formatting correction — 2026-11-06

## Scope and finding

This correction targets ordinary Dope IDE Chat formatting and sidebar presentation at unchanged product version `0.13.8`. The owner-reported FireLaunch retest produced a prose-heavy 12-row Markdown table, 1,955 output tokens and 225.9 seconds total. A separate explicit three-column request produced four columns. Streaming and persistence worked in those observations. These are input evidence, not a new Green qualification.

The previous ordinary response instruction was a system message, but its exception allowed compact tables for “naturally tabular short values.” Its brevity wording was soft and had no rule for a brief request's point length. The backend selects ordinary Chat for an unselected, nonspecialized report turn, and the composer puts this instruction in a system message after the Pi tool instruction and before user/history messages. The local Pi worker joins composer system messages into a system entry before the current user turn; its base Dope authority prompt has no competing table rule. Saved conversation examples may contain tables but are lower-priority history. Specialized Roadmap, Work and protected command instructions are separate paths.

The effective ordinary response instruction is in `packages/theia-extension/src/node/chat-context-composer.ts`. It says to answer directly; default to no Markdown tables; use short headed paragraphs and compact lists even for comprehensive, multi-topic reports; use a table only on explicit request or a specialized task's explicit table contract; preserve exact table headers and column count; follow requested depth and paragraph counts; give brief answers as one short sentence per requested point; consolidate overlap; stop when adequately answered while preserving factual completeness. It also retains the pre-existing read-source/citation guidance and has no hard length cap. It is assembled once for local Pi and hosted ordinary turns, and excluded from specialized turns. The Pi tool-system instruction says project files are not automatically read, file claims require successful brokered reads, and tools are read-only without separate authorization. The Pi runtime's base system prompt concerns Dope authority and tool use; it has no competing format rule. The existing project evidence and document retrieval behavior are unchanged.

The Chat sidebar CSS lets a rendered table retain its Markdown cells and scroll horizontally inside the table box. The rule is scoped to the Chat panel; Work's table presentation is unchanged. Streaming, cancellation and saved answer paths were not changed by this formatting correction. Other pre-existing uncommitted streaming changes remain in the worktree.
