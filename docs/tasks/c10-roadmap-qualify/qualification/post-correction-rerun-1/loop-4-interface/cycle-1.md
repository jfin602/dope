## Browser controller freeze and host restart analysis

The first controller timeout occurred during `reload()` of a browser layout containing the same Chat in multiple docks and a center Roadmap split while Q4 was loaded. The browser controller then returned empty app/browser inventory. The Dope browser service still answered HTTP 200; LM Studio was idle. Host RAM was 30 GiB, about 24 GiB used, roughly 6 GiB available, no swap. Several ChatGPT processes each held multiple GiB resident memory. The previous system journal ended at **2026-10-15 07:24:12 CDT** without normal shutdown and the next boot began **07:31:43 CDT**. The available journal has no OOM, GPU hang, segfault or killed-process entry. Thus the abrupt reboot is observed; its cause is not established.

After reboot, browser reload and a real backend restart **succeeded** on a Roadmap-only view with Q4 unloaded. Later, with Q4 loaded, a single right-docked saved Chat completed normally, but its browser reload after a second backend restart caused another 30-second controller timeout and temporarily empty browser/native inventory. At that time the backend still answered HTTP 200, RAM showed about 8 GiB available and no matching journal OOM/GPU error. After Q4 was unloaded and the controller reset, inventory eventually returned. It explicitly reported browser tab 3 (“dope-p12-interface-replay”) as **“This page crashed”** while the saved Chat tab 5 was live and could be inspected after the restart. This is direct evidence of an in-app browser tab crash; it does **not** establish whether ChatGPT's Linux renderer, Dope frontend load, model memory pressure, or another interaction caused it. The preceding host reboot still has no proven cause.
