## Risk and scope assessment

1. **Test/source authority priority:** A failure in a stale-source protection test cannot be waived merely because it failed during fixture setup. Recreate correct source basis in a disposable fixture and test a real linked file change between stages. If a product source check is wrong, repair it. Attribute teardown ENOTEMPTY based on reproducible evidence and fix owned lifecycle only.
2. **History projection:** Derive ordinary Apply events from actual immutable Roadmap revision receipts/operation IDs with stable event IDs, exact revisions, timestamps, counts and bounded labels. Include genuine restores; do not emit duplicate events for sync or rejected/no-op actions. Never fabricate old records.
3. **Freeze continuous generation:** Keep `roadmap_phase` StageOwner transactions, one Pi execution, next-Phase loader and current source checks. Restrict P3 runner cleanup to demonstrably dead **nonvisual** references only; UI code will change later under manual browser control.
4. **Review controls:** The requested three-icon tab protrudes above the **top-right** of every selectable eligible Phase/Gate/Criterion/Correction. Distinguish checkbox selection from check/X Apply/Reject. Direct element icons still invoke existing reviewed preview/confirmation and backend operation/dependency closure; for Criteria nested inside a Gate create, map to owning operation or explain why individual action is unavailable. No unauthorized direct Apply.
5. **Theme/geometry/accessibility:** No text inside icon buttons; tooltips and labels explain scope; use Dope theme accent only under Dope theme, neutral otherwise. Top-right protrusion must not clip, block expand chevrons, overlap React Flow handles, fail under pan/zoom, rely on hover only, or lose focus at keyboard/zoom/narrow sizes.
6. **One Chat timeline:** Remove redundant post-reasoning tool dropdown, but retain actual tool events in reasoning/activity and saved provenance even if provider reasoning unavailable. Keep copy-with-reasoning, provider-tool chronology, safe diagnostics. Ensure every normal assistant footer is last visible in-flow element: no Roadmap confirmation below it; response-info must be above footer or overlay and correct on expand/reload.
7. **Status density:** Card default is short factual applied/rejected/pending counts and one Details disclosure; warnings remain accessible but do not repeat long user goals or Gate lists in yellow. No invented completion status. The separate auto textual confirmation below actions is a structural UI bug, not a reason to suppress actual error records.
8. **Qualification ownership:** Browser visual changes need manual connected browser passes; runner should not silently start UI. Source tests cannot substitute for browser/native. Explicit independent full-MVP and Electron gaps stay open.
