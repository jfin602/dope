## Contracts and observed behavior

**Tier consistency.** One `validateAssessmentTiers` function checks exact T1/T2/T3 shape, bounded nonempty text, focused source/unit responsibility, integration or cross-boundary responsibility, and independent manual browser responsibility. `assessment_stage`, `assessment_finish`, and final structured Assessment validation call that function. Invalid tier text is rejected before a draft revision is written, with the failing tier and missing responsibility in `ASSESSMENT_TIERS` feedback. Existing accepted valid tiers remain immutable; identical replay stays idempotent.

**Guarded correction.** Only a previously accepted *invalid* tier tuple in an active, unsealed draft can be changed. The model must supply `correctRevision` from `assessment_status`; the store checks exact revision, lease, project/Assessment identity, source basis and existing pages, then validates the replacement. The saved partial draft contains one audit entry with the revision, original and replacement. A normal valid tier tuple, source finding, scope or other category cannot use this path. The legacy-invalid case was constructed in a store fixture because the new stage validator cannot create one. Wrong revision, wrong lease, foreign identity, invalid replacement, valid-tier overwrite and sealed mutation were rejected.

**Readiness.** `assessment_status` now returns `finishReady`, `blockedBy`, `scope`, `tierState`, `acceptedObservations`, draft `revision`, requested file/page progress, category states and one `nextAction`. Its saved-state readiness check is also used by `assessment_finish`. It checks complete requested source ranges, at least one brokered page, observations, preservation, dependencies/risks or justified empty state, scope and the shared tiers. When all those are present, a bounded read of an already-inspected `package.json` applies the same manifest-dependency check used at finish. A contradictory empty dependency claim therefore reports `finishReady:false`. Readiness is provisional: finish still revalidates every source page and citation against current bytes, and source drift can block sealing after a ready status.

**Recovery policy.** The broker allows at most eight **consecutive recoverable failures without verified progress**. A newly accepted finding/category, valid tier repair or newly completed requested file resets the streak. Status polls, partial pages, identical accepted stages, text and denied calls do not. On the next call after eight such failures it emits `ASSESSMENT_NON_PROGRESS_LIMIT` and stops the execution's Assessment tool authority. Wrong owner/lease/project, inactive or cancelled turn, source drift, sealed/stale draft, integrity failure and resource ceilings remain hard stops; unknown internal failures fail closed. The independent 128 broker tool-event ceiling and Pi/provider/time/cancellation limits remain. Saved safe `assessmentOutcome` values distinguish progress, partial source page, idempotence, status, recoverable rejection, hard authority, repeated non-progress and resource ceiling without raw arguments or private reasoning.

**Model guidance and feedback.** The protected instruction now uses `read_file({path})` followed by `read_file({path,continue:true})`; it no longer tells the model to supply `nextOffset` or `expectedSourceHash`. It directs the model to inspect status, read all requested pages, stage a few verified findings, avoid accepted-category replay, stage valid T1/T2/T3, check `finishReady`, and repair by specific rejection feedback. Premature finish returns the missing categories and next action. Citation and conflicting-scope replies remain specific without granting evidence or exposing foreign state.
