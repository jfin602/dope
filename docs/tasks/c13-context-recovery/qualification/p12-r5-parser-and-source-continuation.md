## Broker-owned source continuation — PASS

Protected Assessment `read_file` now uses a verified, ephemeral receipt for routine sequential pages. The first successful offset-zero read records the project-relative path, original source hash and exact `nextOffset`. The receipt is bound to one project root/handle, Chat, execution, lease and owner, and expires after 30 minutes. A hashless next-page call resolves identity only when the active owner, requested source coverage state, path, offset and receipt all agree. The broker passes that original hash into the existing `ChatProjectGrounder.readFileRange`, which rehashes the current file through the opened descriptor and rejects changed bytes. Explicitly supplied hashes still receive their old strict validation and are never silently replaced. Ordinary Chat and other consumers retain the explicit-hash continuation contract. Assessment status and the protected tool description now direct the model to use path plus `nextOffset` instead of copying a 64-character hash.

The receipt has no persistent store and cannot cross a new execution. The broker checks the active turn, lease, project and cancellation both before resolving a hashless continuation and after the file read before granting coverage. Failed reads add no source range. The source owner still validates exact covered bytes and source-backed citations before `assessment_finish`.

Direct receipt negatives passed for no initial read, wrong offset/path, missing or mismatched coverage, wrong source identity, foreign root/project handle/Chat/execution/lease/owner, expiry, inactive or cancelled execution, and completed-page replay. A changed-file check passed the broker-resolved hash into the actual grounder and confirmed `Stale file continuation` after the bytes changed. The real-worker broker fixture also rejected a read before the first page, a foreign path, a wrong explicit hash, an out-of-sequence offset, and a duplicate page, then accepted the hashless correct page. These rejected operations did not contribute coverage.

The same fixture read `docs/late-guide.md` bytes 0–4,096 and 4,096–6,584 without model-supplied `expectedSourceHash`, fully inspected all five source files, accepted six Assessment stages with source-backed citations including the late guide, completed `assessment_finish`, sealed exactly one Assessment record, and reached checked `/prompt-plan` entry. No canonical file was written. The fixture did not exercise an actual UI cancellation or project switch mid-file-read; the receipt's inactive/foreign-context negatives and the broker's pre/post read guards cover those boundaries deterministically.
