## What is confirmed and why this is a correction

The owner asks for the normal ChatGPT-style planning session: provide an idea plus a few requirements, AI inspects the project, produces a **step-by-step implementation plan**, then conversationally revises it. The current repo already supports saved Chat, greenfield Roadmap drafting, validated 1-action or optional 2–3-action graph proposals, preview/approval, canonical linked Markdown, Planning Map impact/transformations and WorkItems/prompt publication. It does **not** expose a distinct complete, human-readable implementation-plan draft as the default idea-first result. That is a **source-supported product-design gap**, *not* independently reproduced GUI breakage. Ledger: UX-017; do not relabel UX-011 or prior browser qualification.

## Design decisions / ownership locks

1. **Primary output:** one useful plan in readable Chat prose, not a stream of one-node JSON proposals. No mandatory questionnaire. Include honest assumptions and an essential clarifier only if it would change the plan. A truly source-unavailable turn may yield a labeled partial plan, never invented grounding.
2. **Plan identity:** versioned bounded noncanonical plan draft with stable step IDs, source/basis revisions and decided-vs-suggested fields. The draft does not become `RoadmapStore`, Markdown, PlanningMap or WorkItem state until that independent owner accepts its transition. Prefer extending `RoadmapGreenfield` over creating competing owners.
3. **Investigation:** read-only deterministic orchestrator reusing `ChatProjectGrounder` and existing map/context services; cap queries, reads, bytes, tokens, generation attempts and cancel; fail closed on path escapes, stale hashes or user change. Do not equip ordinary Chat with unrestricted agent tools.
4. **Local-model contract:** respect selected/ready actually loaded Q4_K_M/32768 **reference**, no global default/provider override, no implicit hosted egress; validated completed structured plan + prose view. Avoid pretending local models reliably emit one massive complete JSON after a short partial stream. Bounded adaptive plan output is compatible with 32K, with recoverable continuation.
5. **Plan editing:** user turns may apply a bounded plan-level revision to the accepted *draft* after review; changed step IDs and dependency impacts visible; unrelated accepted decisions kept. New revision invalidates stale pending reviews. Revisions must not resurrect superseded/implemented P*.txt or qualification.
6. **Projection:** propose all strategic items for *one reviewed draft* in a single experience but implement translation through bounded `RoadmapGreenfield` / `ProjectPlanningActions` owner batches and explicit canonical Markdown approval. Do not inflate low-level technical steps into duplicate Roadmap checkpoints when Planning Map owns them.
7. **Bridge:** existing Prepare Work, current impact/target, WorkItem and stack reviews remain separate. Work Experience recovery owns Work display/launch; Phase Focus owns immutable progress evidence; no overlap with their writers.

## Risks, safety and sequencing

- **Highest technical risk:** full-plan output vs current one-action strict JSON. Do not push raw 10K+ natural prose into `no-action` or raise allowed Roadmap actions globally. P1 schema / P3 parser must cooperate.
- **High risk:** model-reading workflow could accidentally give Chat Work-shell or unbounded repository access. P2 limited read-only packet and denial tests before enabling P3 inference.
- **High risk:** plan becomes a second authoritative Roadmap or Planning Map. P5 strictly owns draft-to-approved projection; tested stale/partial rollback and explicit reconcile.
- **Overlap risk:** shared `chat-backend.ts`, `chat-panel-widget.ts`, `roadmap-canvas-widget.ts`, `frontend-module.ts` and compiled package tests; inspect current Work Experience branch/recovery and local dirty state, touch narrow regions only. No reset/stash/clean/force-push/implicit merge.
- **Performance risk:** repeated local Q4 calls are expensive. First reply should be useful with budgeted evidence. Prefer one synthesis over serial generative microtasks, bounded additional reads only when justified; measure rather than promise latency.
- **Authored order:** once P1–P8 created, don't edit/reorder in place. Different content on unstarted authored stack requires reviewed supersession/fingerprint; completed history always immutable. Manual qualification is a separate T3 outside headless runner.
- **Version:** correction unchanged `0.11.8`, only if actual local project matches; stop/re-assess on advance rather than downgrade. Do not change manifests or internal pins.
- **Evidence:** remote GitHub browse is a design assessment, not local compiler/test, Q4 inference, direct browser/Electron or full phase qualification. Existing Phase 11 remains OPEN / NOT QUALIFIED, Phase 12 inactive.
