## Deterministic integrity and safety

- Generated Markdown is deterministic and round-trips Phase, Gate and Criterion IDs, titles, objectives/purposes, expected results, parentage, designations, ordering and dependencies through the existing parser. Published bytes, SHA-256, seven section mappings and last-synced fields agree. Linking compares the accepted structure to parsed existing bytes and requires explicit Order and Dependencies metadata; missing or changed mapped fields block direct linking.
- Existing-link approval is bound to the owner-issued review, project ID/root, revision, relative path, source SHA-256 and compared fields. Cancel, changed index revision, changed source bytes, incompatible topology and a parent swapped to a symlink after preview do not link or rewrite the document. Duplicate result delivery is idempotent, including after owner reconstruction. Existing-link interruption before index persistence leaves no link; response loss after persistence replays the confirmed single link.
- New-file publication retains a durable pending intent before exclusive creation. Tests cover interruption before creation, after creation before linked persistence, damaged staging bytes, changed destination during recovery, response loss after persistence, competing publication previews, occupied destination and root/path safety. Changed recovery bytes remain untouched and noncanonical. A nested published file relinks to another safe existing nested directory, then syncs after restart.
- Corrections have a parser form but the current publisher cannot round-trip their accepted schema-2 fields and relationships. Both publication and direct existing-file linking therefore reject an accepted Roadmap containing Corrections **before** any Markdown write or link. No representation was invented. Publishing or linking never approves criterion evidence, Gate-set coverage, Gate/Phase Green or implementation completion.
