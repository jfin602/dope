STORAGE LAW

Durable Software Map truth is intentionally small:
- `.dope/architecture.json` = canonical developer-owned architecture;
- `.dope/smap.json` = accepted initialization marker bound to exact architecture bytes.

Keep transient/rebuildable:
- synthesis reviews/drafts;
- evidence packets/proposals;
- Physical Map snapshots/indexes/compiler programs;
- coverage ledgers;
- synthesis attempts/cache/progress;
- Search Deeper previews;
- provider/model setup and credentials;
- UI/workspace state.

Do not persist any of those merely to satisfy this correction.

AUDIT FIRST

Before changing product source, verify from current implementation:
1. canonical architecture is read only from project-local `.dope/architecture.json`;
2. initialized state is derived only from a valid matching project-local `.dope/smap.json`;
3. marker identity does not encode absolute project paths;
4. fresh backend attach re-reads initialization from project files;
5. Physical Map state is rebuildable from source/config/canonical architecture;
6. provider/preferences/cache/session state is not required for project truth;
7. project switching clears transient review/provider state;
8. malformed/mismatched/symlink state already fails closed.

PERMANENT PORTABILITY REGRESSION

2. accept canonical architecture through the real SoftwareMapBackend/service acceptance path;
3. require ready Physical Map state and record canonical System/Subsystem/Component identity/containment;
4. dispose the backend/index;
5. copy the repository INCLUDING `.dope/` to a different filesystem root;
