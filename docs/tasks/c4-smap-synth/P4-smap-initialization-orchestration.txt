TASK: Correction 4 / P4 — Local LM Studio Qwen synthesis provider

MODEL / REASONING / USAGE
- Recommended configuration: `GPT-6 Sol High`.
- Browser required: no.

VERSIONING
- Required unchanged project version: `0.4.6`.

GOAL

Implement the first concrete ArchitectureSynthesisProvider through a local LM Studio-compatible OpenAI-style HTTP endpoint, including model discovery, strict structured-output capability probing, explicit pre-synthesis warm-up and hard prevention of project-evidence submission when readiness fails.

PREFLIGHT

Read current authority, ADR 0011, this correction assessment/plan and exact successful P1-P3 source/results.

P3 added deterministic framework extraction and is part of the ArchitectureEvidencePacket supplied by this provider.

Require exact P3 predecessor, clean intended Git state and package `0.4.6`.

BOUNDARY

Keep the concrete adapter in the backend/application integration layer. Do not create the Phase 6 general Model Runtime/Agent Runtime, do not import LM Studio types into `@dope/software-map`, and do not add a large AI SDK merely for the narrow HTTP path.

Use the P1 provider-neutral interface and proposal schema/validator.

CONNECTION / MODEL DISCOVERY

Support:
- safe loopback/default LM Studio-compatible endpoint probing;
- explicit validated http/https endpoint with no embedded credentials;
- model enumeration from the compatible API;
- recognition/preference of Qwen3-Coder-30B-A3B-Instruct as the reference family while preserving the runtime's actual model ID;
- optional bearer/token input without requiring it for ordinary local use.

Do not persist provider config into project files.

STRUCTURED-OUTPUT PROBE

Implement a tiny synthetic schema-constrained request that verifies:
- endpoint reachable;
- selected model available;
- structured JSON/schema response works;
- response parser works.

The probe payload must contain no project/repository evidence.

WARM-UP HARD GATE

Implement explicit readiness immediately before the first real packet synthesis:
- synthetic tiny request only;
- no ArchitectureEvidencePacket/project text;
- warm state keyed at least by normalized endpoint + selected model;
- invalidate on connection/model failure/change/reconnect/known unload;
- avoid redundant warm calls for bounded follow-up synthesis while known warm.

If warm-up fails, the implementation must issue zero real packet synthesis requests.

SYNTHESIS

Only after warm readiness:
- send the deterministic ArchitectureEvidencePacket;
- require strict ArchitectureProposal structured output;
- run P1 schema/reference validation against the exact packet;
- fail visibly on invalid/refused/malformed output;
- return only structured product fields, not hidden reasoning.

PERMANENT TESTS

Use a controlled in-process/mock HTTP server.

Prove exact request ordering and data separation:
1. model discovery;
2. capability probe with no project evidence;
3. warm-up with no project evidence;
4. real packet request only after successful warm;
5. bounded follow-up may reuse warm state;
6. warm failure => no packet request.

Also cover timeout/network error, HTTP error, invalid JSON, schema-invalid response, fabricated evidence refs, auth redaction and warm invalidation.

Do not depend on the user's actual LM Studio process in permanent tests; P7 owns live qualification.

Run focused provider/domain tests, `npm run check`, restart, correction validation, unchanged-version/coherence checks and `git diff --check`.

SCOPE

No frontend setup UI yet, no canonical persistence/acceptance, no cloud provider, no bundled inference runtime.

FINAL RESPONSE

Report adapter location/API behavior, probe/warm data-separation proof, request ordering, validation/error handling, tests, checks and readiness for P5.
