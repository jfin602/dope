After each generated hierarchy is frozen, compare it against the same independent developer/reference architecture sources used by predecessor P8 where available. Never feed those references into synthesis to patch the run.

Valid refs are necessary but not sufficient for Green architecture quality.

DIAGNOSTIC COMPARISON

Use the ADR 0013 categories:
- similar architecture + much slower Local calls => evidence for local model/runtime bottleneck;
- materially better Gemini architecture from equivalent input => evidence for model capability difference;
- both slow/oversized => evidence for shared synthesis/planner bottleneck;
- both materially improved over predecessor => evidence that prose-heavy intermediate protocol was a bottleneck.

State evidence and uncertainty. Do not perform the next Local optimization inside P4 merely because the result points to one.

UI / SECURITY / LIFECYCLE MATRIX

Directly prove:
- Local and Gemini sections collapse/expand independently;
- Gemini cloud disclosure is visible;
- key is masked and never shown back;
- environment-key status reveals no value;
- no key appears in StorageService/preferences, `.dope/`, logs, progress, telemetry, evidence, cache identity, review or surfaced errors;
- selected provider is obvious;
- no Local -> Gemini or Gemini -> Local fallback;
- Local probe/warm-up still works;
- Gemini readiness works;
- cancellation and retry remain usable;
- switching provider/root/project rejects stale results;
- existing/manual architecture remains usable without provider where expected;
- review/source navigation works;
- developer correction and explicit acceptance remain the only canonical transition.

Perform at least one controlled selected-provider failure proving no fallback and no project evidence is sent to the unselected provider.
