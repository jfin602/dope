## Implementation details

**P1:** Keep provider interfaces additive and preserve non-Pi models. The Pi worker currently handles text_delta only; inspect installed Pi version/types rather than inventing thinking event availability. Explicit thinking can be captured if exposed; plain text should be provisional during streaming until a genuine terminal completion. After successful completion store one authoritative final answer; partial output after cancellation/error belongs only to diagnostic activity. Keep existing Chat repository ID/lease/atomic mutations, source refs, tool-progress policy, and context budgets. Default caps: 128 KiB diagnostic text / 512 entries per execution, with explicit truncation. Avoid promoting failure drafts from legacy records. No hidden provider thought recovery.

**P2:** Render activity in a bounded gray disclosure, with active status/elapsed, typed labels, incremental rendering and per-message expansion state. Success collapses activity and shows one formatted final answer. Cancellation/failure shows status and inspectable activity but no invented final. Migrate/adapt existing Planning raw-output and tool activity displays carefully; don't turn rejected Planning JSON into a clean answer. Audit server ChatContextComposer, title, saved-chat search and Roadmap source consumers to ensure activity remains excluded. Keep ChatPanel docking, markdown, scroll-follow, text selection and Space-drag/touch mechanics.

**P3:** Use one reusable menu/serializer, not duplicated handlers or extra permanent CTA. Normal left click of Copy Response = clean committed answer, Copy Transcript = clean chronological dialogue, Copy JSON = explicit raw JSON. Right click on a Dope-owned Chat copy control (and associated Chat/Work transcript copy where relevant) opens small scoped menu with Copy with Reasoning. Keyboard Context Menu/Shift+F10, arrow navigation, Escape and focus return. Missing captured reasoning presents a disabled option and explanation; provider-hidden thinking is never exposed. Export chronological captured activity and status plus any final response, with redacted tool detail and honest truncation markers. Export does not modify stored Chat, model context, grants or Roadmap.

**P4:** Real Codex connected browser is the final gate, not a unit-test substitute. Use a disposable project with src/counter.js and another real project-aware conversation, actual available local model/provider, and a controlled 12-paragraph reasoning/provisional cancel fixture. Check successful final answer, cancelled no-final, copy variants, reopen, copy keyboard/right-click, no context contamination and tool redaction. Then record owner-operated AppImage separately; if unavailable, mark EVIDENCE GAP. No browser automation from the headless runner.
