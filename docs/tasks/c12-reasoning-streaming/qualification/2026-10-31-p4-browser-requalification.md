## Off diagnosis and repair boundary

The saved Off setting was verified in the Chat record. `pi-conversation-runtime` now explicitly tests forwarding `reasoningMode: 'off'`; `pi-model-bridge` and the pinned worker tests prove conversion to Pi's Off level and `chat_template_kwargs.enable_thinking = false` in their deterministic transport. The real UI still received genuine provider reasoning. Two direct read-only requests to the same loaded LM Studio OpenAI-compatible `/v1/chat/completions` endpoint, one with `chat_template_kwargs.enable_thinking=false` and one with `reasoning="off"`, each emitted reasoning and reached a 128-token `length` stop with empty final content. This is evidence that the current provider path did not honor those controls in this configuration; it does not justify hiding genuine emitted reasoning or fabricating a text-only answer. [LM Studio's native chat API](https://lmstudio.ai/docs/developer/rest/chat) documents a `reasoning: "off"` option, while its [API comparison](https://lmstudio.ai/docs/developer/rest) distinguishes the native endpoint from the OpenAI-compatible custom-tool path. Changing Pi's endpoint or disabling a reported capability needs a separately scoped adapter repair and live requalification; no safe surgical product patch was established within this closeout.
