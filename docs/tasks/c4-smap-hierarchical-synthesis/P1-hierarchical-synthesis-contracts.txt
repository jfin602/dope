CONTRACT DIRECTION

Do not preserve `ArchitectureSynthesisProvider.synthesize(packet)` merely for internal compatibility.

Create a provider-independent stage-capable boundary suitable for the ADR 0012 flow:
- System Discovery;
- System Challenge;
- per-System Subsystem/Component discovery;
- reconciliation;
- targeted verification.

Keep concrete LM Studio/Qwen details out of `@dope/software-map`.

Define the smallest coherent strict types/schemas for:
- provider/model synthesis capabilities, including usable context/input budget information and any provider-supplied token estimate/count seam;
- parent ArchitectureEvidencePacket identity;
- deterministic evidence-view/slice identity;
- stage name/version and stage request metadata;
- System candidate output;
- challenge decisions capable of keep/merge/split/reject;
- per-System subtree output;
- reconciliation/verification results where needed;
- final ArchitectureProposal assembly inputs;
- safe user-visible progress events.

Do not over-generalize into Phase 6 Model Runtime.

CONTEXT BUDGET CONTRACT

The domain must not hardcode 32,768 or 65,536.

Represent enough capability so orchestration/evidence planning can:
- know the usable model context/input ceiling;
- reserve instruction/system text;
- reserve structured output;
- reserve provider/safety overhead;
- ask a provider/adapter for token estimation/counting where available;
- use a conservative provider-defined estimate where exact tokenization is unavailable.

The budget is a hard request-safety boundary, not a target to fill.

PROVENANCE / SLICE CONTRACT

A model-facing slice/view must:
- name the complete parent packet fingerprint;
- preserve original packet evidence IDs;
- contain whole evidence items;
- have deterministic identity/version;
- remain proposal input, not evidence authority.

Do not create a second evidence namespace that cannot resolve back to the complete packet.

STAGE OUTPUT VALIDATION

All model stage output is untrusted.

Add strict validation for:
- duplicate/unknown candidate IDs;
- fabricated evidence refs;
- invalid merge/split references;
- invalid parent/kind relationships;
- cross-stage references to nonexistent candidates;
- malformed confidence/uncertainty fields where used;
- invalid stage names/versions.

Temporary intermediate IDs must not become canonical architecture IDs.

PROGRESS EVENT CONTRACT

Define typed provider-independent analysis progress events.

Support at least:
- collecting-evidence;
- planning-evidence / building-skeleton;
- system-discovery;
- system-challenge;
- subsystem-discovery;
- reconciliation;
- verification;
- preparing-review;
- completed;
- failed;
- cancelled.

Safe metadata may include:
- stage;
- status;
- subject;
- completedUnits;
- totalUnits only when actually known;
- provider/model label;
- attempt;
- elapsedMs;
- concise user-facing message.

Do not expose raw prompts, hidden chain-of-thought or model reasoning text as progress state.

PERMANENT TESTS

Extend synthesis/domain tests for:
- valid/invalid stage requests/results;
- capability/budget validation;
- parent-packet/slice evidence integrity;
- merge/split/reject validation;
- progress-event validation;
- no canonical IDs inferred from temporary stage identity;
- no LM Studio/Qwen type leakage into Software Map.

Run focused synthesis/service tests, `npm run check`, restart suite, correction validation, unchanged-version/coherence checks and `git diff --check`.

SCOPE

No deterministic evidence planner yet beyond contract helpers, no real System prompts/calls, no progress UI, no Phase 5 canvas, no general Model Runtime.

FINAL RESPONSE

Report the exact contract/API change, context-budget representation, stage schemas/validators, progress-event contract, compatibility removals, tests/checks and readiness for P2.
