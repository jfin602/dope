# Shared contract for each P3-R2 slice

**Mode and limit.** Manual T2/T3 qualification only, about 10 minutes of focused active work and one live case per evidence session. Repeat the same prompt in a later session for its next case. Setup, model latency and long mechanical checks can take more wall time. No phase runner, automatic closeout, self-commit of product source, version advance, or Roadmap Gate/Phase GREEN. Use the connected browser, actual rebuilt Dope frontend/backend, verified local Pi coding model, and real Dope-brokered tools for a T3 claim. A source/test double is T2-only. Use native Electron only if a native window exists; an Electron build is not native GUI evidence. Work only in a disposable Git fixture, never the owner's persistent projects.

**Read once at entry, then recheck changed facts.** Read `BOOT.md`, `AGENTS.md`, `docs/workflow.md`, ADR 0059 and ADR 0027/0028, `docs/planning/p13/work-tool-selection-proposal.md`, the current one-off Work session/History contracts, P1/P2/P3/P3-R1 reports, the original P3-R2 prompt as historical broad scope, and the paused checkpoint. Inspect actual Git HEAD, version, `git diff --binary` SHA-256, relevant untracked files, bundle hashes, fixture HEAD/status, model/runtime/settings and the saved P3-R2 evidence. The checkpoint's hashes are historical, not an assumed current basis. Preserve owner dirty work and all previous reports, runs, screenshots and fixture records. Never reset, stash, clean, or overwrite them. Do not fabricate the missing `0.14.0` baseline.

**One result per session.** Before a live attempt record source/bundle/fixture fingerprints, chosen mode, project/task/model, selected tools, grant/source review and before file hashes. Afterward record run/session/segment IDs, time/order of broker calls, safe tool names and outcomes from the originating saved transcript, journal and History receipts, exact after hashes, Git state, validation snapshot/result/applicability, and screenshot paths with SHA-256. Capture an active editor/preview image *before Finish* when the case depends on active visibility. Store one new dated result under `results/` and raw artifacts under `evidence/p3-r2-slices/`; cite existing P3-R2 files by path/hash rather than copying or rewriting them. Redact protected arguments, credentials and private source from reports while preserving safe tool outcomes.

**Repair and source epochs.** Repair only a defect demonstrated by source or live behavior, with a narrow regression and replay of the affected slice. Keep broker, selected-tool/grant ceiling, path confinement, journal-before-write, owner source basis, Isolated candidate, validation and Roadmap authority intact. Record the source fingerprint before and after any repair. Earlier live evidence belongs to its original source epoch; it is not silently upgraded to final-source PASS. Rebuild/restart and reverify provider capability as needed. If a case cannot complete in the target window, safely Stop or Finish any active run, preserve applied bytes and journal truth, write PARTIAL/FAIL/BLOCKED with the exact next step, then end that slice.

**Decision rule and revised scope.** PASS requires the exact observations named in the current numbered prompt. A model refusal or malformed call is not evidence that the requested broker operation was denied. An unsuccessful attempt remains visible even after a passing rerun. Never call a T2 test a live T3 result. This owner-directed pass is limited to one-off New Work and its own follow-up/recovery, plus the Direct ownership, broker authority and Isolated regression cases listed in this slice matrix. WorkItem, Prompt Stack/phase-stack and linked Roadmap qualification are deferred and retain their prior unqualified status; by the owner's 2026-11-26 scope decision, their absence is not a required technical P3 GREEN blocker. Technical P3 GREEN under this amended scope requires the remaining applicable slice cases, exact final-source checks and independent review to pass. Preserve the broader historical P3 prompt and reports without retroactive qualification. Keep native availability and release/version readiness separate from technical browser qualification; no Roadmap Gate/Phase GREEN follows from it.
