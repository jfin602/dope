# P3 project-local activation contract

Implementation basis: `98deaef40d93b113b55902899764d316b6a15341`, version `0.13.11`. This is a runner checkpoint candidate, not a product Gate receipt.

The P2 catalog remains `mcp-servers.json` in the OS-user `aiConfigDirectory()` with `version: 1`, monotonic `revision`, and per-server `id` plus `registrationRevision`. The latter changes on remove/recreate. P3 stores `mcp-project-preferences.json` in that same machine-local directory, not in the project or `.dope/`. Its `version: 1` snapshot contains a monotonic `revision` and `{projectKey, serverId, registrationRevision, enabled}` preferences. `projectKey` is SHA-256 of the exact absolute real root path and filesystem device/inode; lexical aliases, symlink roots/components, and missing/non-directory roots are rejected. Moving or recreating a root defaults off. A cloned repository at a new root defaults off. A same-root copied repository after deletion also defaults off when its filesystem identity changes.

Writes require the current preferences revision and use an OS-user lock, an initialized marker, a synced temporary file, atomic rename, and directory sync. Stale windows reject and must re-read. Missing initialized or corrupt preferences fail closed. An old preference with the same server ID but a different `registrationRevision` is inert. The backend checks the current catalog before enabling; effective state always intersects current catalog identity with the preference. Registry removal invalidates eligibility immediately on the next read, and registry change notifications revoke adapter generations.

The RPC service `/services/dope/mcp-project-activation` is connection-scoped. `switchProject(root?)` revokes the previous generation before validating/loading the next root. `current()` returns the current project key, both revisions, and per-server state/eligibility. `setEnabled` requires the attached `projectKey`, exact server ID/registration revision, and expected preferences revision. It does not grant tool permission, start a transport, or expose project data. `notifyMCPProjectActivationChanged` emits `{generation, projectKey, kind, revokePrevious: true}` on project switch, selection, registry change, and disposal. P5/P6 adapters must cancel pending calls and discard sessions on every event, then re-read both stores before any new eligibility check. Selection alone never authorizes a call.

`disabled` means unselected or globally disabled; `unconfigured` means selected but missing required configuration; `uninstalled` means the preference points to an absent catalog server; `unavailable` is reserved for a selected/configured server when future transport health reports failure; `active` means selected/configured/eligible, not connected or approved for a tool call. P4 should label these distinctions plainly. P5 owns health input; P6 owns per-call broker authorization.

Focused automated tests cover opposite project states, fresh project off, restart, stale cross-window revision, foreign project-key denial, symlink and lexical-root rejection, uninstall/reinstall, project-switch revocation, and no project-local writes. No server or Pi tool is started here. P10 real browser/native and actual Godot bridge qualification remain independent.
