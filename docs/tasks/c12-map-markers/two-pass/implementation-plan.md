# Implementation plan — two automatic local-model passes within one Chat turn

## Current versus target

**Current:** eligible revision-zero protected `/roadmap` → `ChatBackend.runTurn` → one `generate()` required to produce strict RM1 → `parseRoadmapMarkers` → `stageTypedRoadmapDraft` / `RoadmapNativeStageOwner` → Chat proposal + Roadmap canvas. M3-R2 real Qwen failed by spending most of its budget deliberating about formatting.

**Target:** same protected saved user turn and selected model → **pass 1: human-readable Roadmap** → **backend durable immutable lock** → **pass 2: strictly mechanical RM1 conversion using a fresh, minimal context** → `parseRoadmapMarkers` → **same** native proposal/canvas review and manual Apply. One user Chat message, one assistant message, one execution identity and one terminal outcome. No model tool-call staging, no separate Chat, no second Roadmap store, no accidental canonical/History/Markdown writes.

## D1 — natural plan and verified durable lock (T2)

**Primary boundary:** `packages/chat/src/{index,service}.ts`, `packages/chat/src/node/chat-repository.ts`, `packages/theia-extension/src/node/roadmap-local-model.ts`, and minimally `ChatBackend` as necessary. Plan 1 prompt should ask for a readable plan with explicit Phase headings, Gate labels and plain observable acceptance bullets; **not** RM1, JSON, a model-owned operation list or repeated format policing. Support 2–12 Phases generically; the exact tower-defense task needs >=5. Bounded completion/finishReason/bytes and recognize a plausible full outline; give unmet-coverage warnings rather than inventing Gates or treating reasoning as final. This is untrusted text, not an operation.

Add an optional strictly parsed, bounded `lockedRoadmapPlan` / equivalent on the existing saved assistant record, containing **exact immutable final-plan bytes**, sha256, schema version, project/root owner identity, source/revision basis, original Chat/user/assistant/execution identity, creation time and a well-defined noncanonical status. Implement checked **write-once** pending-assistant lock at the repository's established locking/revision/lease seam. Require original message and execution still current and matching protected owner, verify expected hash and source preconditions. Ensure old saved chats deserialize, foreign/replacement/cancelled locks cannot be authored or reused, and crash recovery preserves a committed lock while marking the interrupted execution truthfully failed. No transient activity file or UI-controlled mutation may become the source of authority. Do not finish the assistant at pass 1 or create an extra assistant message. The locked text should be viewable even if pass 2 later fails, but **inert** on a historical/reloaded message.

**Tests:** `test/unit/chat-repository.test.ts` + `test/unit/roadmap-local-model.test.ts` plus a directly affected Chat schema test for parse/serialization; exercise lock/restart/invalid hash/overlimit/cross-owner/double-write/failed conversion/no canonical write. First build changed `@dope/chat` if lib-backed, then affected extension only if changed. No inference/browser.

## D2 — automatic conversion and one-turn integration (T2)

**Primary boundary:** `ChatBackend.runTurn`, relevant local-model helpers, explicit model-routing/PI bridge, Chat progress/card if absolutely needed. Consume exactly the D1 locked final text, verify its hash and source basis under current project/Chat/turn/lease. Invoke the **same exact user-selected local model**, or one freshly verified identical Interactive target. Never silently reroute to another provider/model after pass 1. Second model call is automatically started in the **same active Chat execution** without user input or a second append-user/begin-assistant. The second call's messages are built **from scratch**: one short trusted RM1 conversion instruction + one user message containing only the locked plan. Exclude all earlier reasoning, previous Chat messages, original user prompt, built-in skill body, accidental GATE_ACTION JSON guidance and earlier system scaffolding. No tools, no new inference after a failed conversion, no model self-approval.

Constrain conversion output to exact `RM1 P/G/C END`, deterministic one-to-one mapping from recognized locked Phase/Gate/acceptance statements to typed candidate. Validate structural count/order, recognizable source text, and named required mechanics against the **locked original and current request**; do not claim a semantic equivalence theorem for arbitrary prose. Fail closed on ambiguous equivalence, missing or added Gates/Criteria, changed requirements, truncation, source identity/lease drift or mismatch. Preserve the good locked plan on failure; show plan and reason in one saved response, and offer **Retry Conversion** as a later explicit authorized path if supported, never an automatic third pass. Call existing `stageTypedRoadmapDraft` and current checked review/Apply. Before publication verify one atomic terminal Chat finish, one status card, accurate count and no canonical write.

**Important seam:** current `runTurn` currently calls `finish-assistant` on the first completed generator event and then stages; for two passes that completion must be treated as INTERNAL until conversion/staging decides the one final Chat outcome. Capture per-pass time/usage/finish reason without conflating totals or replaying pass 1 deltas as pass 2 final content. Single `AbortController`, stale-source/lease checks at the lock and before/after conversion. Future generation turns cannot pick up the locked content as implicit model history/approval.

**Tests:** focused `test/unit/chat-backend.test.ts`, `roadmap-local-model.test.ts`, `roadmap-typed-stage.test.ts` and Chat panel/controller case only if presentation changed. Mock two generators and assert exactly 2 calls, one Chat user/assistant, D1 persistence between calls, second outbound context isolated, same model and no fallback; pass 2 valid→checked preview/no write; invalid/truncated/missing/mismatched/cancel/owner switched→durable inert plan and zero effects. Run directly affected package builds in dependency order and `git diff --check`. No browser/Qwen.

## D3 — single Codex Browser real task and dogfood-entry closeout (T3)

Verify local HEAD, dirty files, selected model, one running Dope browser server and exact served bundle/backend hashes; `npm run build:browser` includes extension, so no redundant build. Use **Codex Browser only** and a disposable TypeScript/PixiJS project. Submit original >=5-Phase tower-defense brief once. Observe **two model calls within one saved Chat turn**, natural plan locked and inspected, converter receives only frozen plan, final RM1 reviewed candidate, and durations/token usage for each pass where reported. Verify all requested waypoint/enemy/target/projectile/cooldown/wave/money/health/defeat mechanics, nested criteria, noncanonical preview, canvas select/pencil/checked Apply, linked Markdown/reload and accepted Gate → Prepare Work. No actual Work run. One baseline plus at most one observed in-scope focused repair/retest, not repeated expensive model loops.
