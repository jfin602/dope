## Hard UX contract

1. **Phase-first readability:** Large, proportionally spacious horizontal Phase cards with readable Gate summaries/criteria at normal usable zoom. No automatic Fit-All downscaling to squeeze every Phase onto screen. More than one screen of phases is fine; pan/scroll horizontally, Fit All explicitly optional. Use responsive/minimum dimensions and keep text selectable.
2. **Visible progression:** Unplanned neutral/dim, Planned warm copper, Active restrained Dope orange, NOT GREEN/Blocked muted red, GREEN actual evidence-qualified green, stale/unknown/waived distinguishable. Color accents, progress track and route cues are materially visible, with explicit labels/noncolor icons and dark/light/high-contrast themes. A proposed Gate does not promote a Phase or fabricate completion.
3. **Chat-first authoring:** The existing dockable saved ChatPanel, **not another editor or assistant**, is the primary interface to create, revise, reorder and remove Phases/Gates/criteria, dependencies/corrections and review qualification evidence. Chat proposes bounded typed, current-project/current-revision changes via existing Roadmap service/ProjectPlanningActions and authorizing preview/diff/Accept/Reject. Never permit a model to claim Gate Green from prose or bypass explicit evidence/owner approval. No raw JSON presentation or menu-heavy Gate wizard.
4. **Read-only inspection by default:** Selecting a Phase or Gate displays useful details in the existing in-stage Software Map-style inspector. Only an explicit **Edit** toggle enables local field editing; toggle off/discard/cancel restores read-only. Both Chat and local fields use exactly the same authoritative typed edit path. No always-on input fields or status dropdowns that can assert Green.
