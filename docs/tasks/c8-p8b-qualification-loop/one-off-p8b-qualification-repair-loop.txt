PHASE 8B CONTRACT TO PRESERVE

The default accepted ExecutionGrant is fixed for 8B.

Allowed:
- project read/observation;
- project workspace mutation;
- project-local process/test/build;
- Git inspection.

Denied:
- Git stage/commit/reset/rebase/checkout/switch/history mutation;
- network from model-directed project execution;
- secrets/credential access;
- private HOME/user-state access;
- outside-project read/write/effects;
- destructive/system/package-administration effects.

Additional laws:
- the developer accepts the grant before mutation;
- provider/model/repository text cannot widen it;
- unsupported enforcement fails closed;
- prompt instructions are not enforcement;
- the Phase 8A Test Connection remains read-only and separate;
- no ChatGPT-plan -> generic OpenAI API-key billing fallback;
- provider-native thread identity is recovery metadata, not AgentTask/AgentRun identity;
- no fallback after meaningful mutation/output;
- Stop must terminate real execution and preserve already-written project changes;
- restart may reconcile a dead in-flight run to interrupted but must not automatically continue it;
- .dope/agent state must not persist OAuth tokens, hidden reasoning, arbitrary environment dumps or unbounded provider payloads;
- 8B never stages or commits the target repository;
- Phase 8C sequencing remains out of scope.

CYCLE 1 - START WITH REAL SANDBOX STARTUP

The first goal is NOT to get a model to run.
The first goal is to prove the local execution sandbox can start and enforce the accepted grant against a deterministic non-model probe.

Diagnose the current failure before changing source.

Answer from evidence:
- What exact executable path is resolved for Codex?
- What exact command/argv reaches the sandbox command?
- Is the failure from Codex argument parsing, config/profile loading, bubblewrap setup, mount visibility, or payload exec?
- Which path does bubblewrap report it cannot exec?
- Is that path the Codex launcher itself, a Node entry point, /bin/sh, or another payload?
- Is the installed Codex a symlink/wrapper whose real target is outside the sandbox-visible filesystem?
- Does a minimal current official read-only or workspace-write sandbox command start successfully outside Dope?
- Does a minimal workspace-write command using the same CODEX_HOME start?
- Does selecting dope_run cause the failure?
- If dope_run fails, which exact profile rule is incompatible?
- Does :root deny or another filesystem rule hide the executable/runtime required to bootstrap the sandbox itself?
- Does project trust/config layering prevent the expected profile from loading?
- Is the preflight testing something stricter/different from the actual App Server execution path?

Use a bounded config/profile bisection if needed, but never accept a weaker final policy merely because it starts.

The repair must make the deterministic probe execute and prove all of these in one run:
- permitted project file write succeeds;
- outside-project canary read/write is denied;
- private HOME/credential-like canary read/write is denied;
- .git control/history write is denied;
- project secret-pattern file such as .env is denied according to the approved contract;
- network attempt is denied;
- destructive/system/package-admin canary action is denied or made unavailable under the enforceable 8B policy;
- ACCESS_TOKEN/provider credential material is not readable by model-directed shell;
- target repo HEAD remains unchanged.

If the current Codex sandbox cannot express/prove the full fixed 8B grant, do not weaken the grant. Record the capability gap. A materially new sandbox architecture requires a separate architecture decision rather than an improvised loop repair.

After the smallest repair:

ITERATIVE CYCLE ALGORITHM

For cycle = 1 through 5:

1. QUALIFY
   - Start at the first currently unproven gate above.
   - Reproduce it directly.
   - If it passes, continue to the next gate.
   - Stop at the first newly observed blocker.

2. DIAGNOSE
   - Trace the failure to exact source/runtime/provider evidence.
   - For Codex behavior, verify current official docs and actual installed CLI help/version.
   - Record the failure boundary before editing.
   - Do not log secrets.

3. REPAIR
   - Make the smallest bounded repair inside the existing Phase 8B contract.
   - Keep version 0.8.13.
   - Do not relax the ExecutionGrant.
   - Do not pull Phase 8C/8D scope forward.
   - If a real fix requires a new sandbox architecture, stop and record that architectural blocker rather than hiding it inside a repair cycle.

4. FOCUSED REGRESSION
   - Run only tests/builds invalidated by the repair.
   - Add a permanent regression for the observed defect when feasible.
   - Always run git diff --check, no-root-lock and 0.8.13 coherence.
   - Do not run npm run check after every small repair unless the changed boundary genuinely invalidates broad integration.

5. REPLAY
   - Repeat the exact direct gate that was blocked.
   - If Green, continue through the remaining gates in the same cycle until another blocker appears.
   - Controlled tests never substitute for the explicitly live/native gates.

6. CHECKPOINT
   - Append cycle-evidence.md:
     - cycle number;
     - pre-cycle HEAD/tracked-tree identity;
     - blocker;
     - direct evidence;
     - diagnosis;
     - files changed;
     - focused validation;
     - replay result;
     - cleared gates;
     - next blocker or all-Green state.
   - Preserve the historical P7 candidate identity even if the current loop now creates commits.
   - If the actual checkout begins with the P7 candidate still uncommitted, do not discard it. At the end of the first coherent cycle, it may be included in the normal loop checkpoint.
   - If the candidate has already been checkpointed for preservation, do not recreate or squash it.
   - For a coherent changed cycle, create one normal checkpoint commit:
     c8-p8b-qualification-loop/cycle-N: <short blocker/repair summary>
   - Never squash away earlier failed-cycle evidence while the loop is active.

7. STOP TEST
   - If every Phase 8B gate is Green, stop immediately and run the full exact-candidate gate.
   - Otherwise proceed to the next cycle.
   - After Cycle 5, do not start Cycle 6.
