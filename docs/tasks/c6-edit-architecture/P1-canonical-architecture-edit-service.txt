IMPLEMENT

1. Make the editor draft projection lossless.

   Current `ArchitectureReviewNode` / `reviewDeclaration` omit canonical Subsystem dependency constraints.

   Establish one shared editor-draft projection that can round-trip every current `ArchitectureDeclaration` field, including:
   - stable canonical IDs;
   - name/purpose;
   - System optional roots;
   - Subsystem required roots;
   - Component roots;
   - parentage;
   - Subsystem `allowedDependencies`;
   - Subsystem `forbiddenDependencies`.

   Prefer evolving the current review/editor node + projection helpers rather than creating a second competing editor model.

   Add a deterministic canonical-declaration -> editor-draft helper with stable editor keys suitable for later branch editing.

   Preserve initial synthesis review behavior.

2. Preserve diagnostics and validation.

   `reviewDeclaration(...)` or its shared successor must reconstruct a full canonical declaration without dropping dependency constraints.

   Invalid dependency targets/conflicts created by edits must surface as deterministic blockers through the existing parser/diagnostic path.

   Do not silently repair or discard constraints.

3. Add a narrow initialized Architecture read API to `SoftwareMapService`.

   It must:
   - require a valid attached project handle;
   - require initialized Software Map;
   - read canonical Architecture through the existing safe reader;
   - return a clone plus current declaration fingerprint/basis.

   Do not expose raw filesystem paths as authority.

4. Add a stale-guarded initialized Architecture save API.

   It must:
   - require initialized Software Map;
   - accept expected current declaration fingerprint;
   - validate the full replacement declaration;
   - call existing `replaceArchitecture`;
   - use a no-op companion transaction for direct editing rather than touching PlanningStore;
   - reject stale architecture/marker state;
   - preserve project-handle isolation.

   Do not modify `replaceArchitecture` unless genuinely necessary. If you do, preserve Visual Planning adoption rollback semantics and prove them with focused tests.

5. Re-analyze after canonical commit.

   After successful canonical replacement, invoke ordinary `SoftwareMapIndex.analyze(root)` so the Physical Map reconciles against the new Architecture.

   The service response must make the outcome unambiguous:
   - canonical save committed;
   - new fingerprint/basis;
   - resulting Software Map status.

   If deterministic re-analysis returns failed after the canonical commit, report that failed map status truthfully. Do not claim the canonical save rolled back unless it actually did.

6. Keep accepted-edit work non-persistent.

   P1 must not create or write:
   - `.dope/smap-analysis.json` for accepted editing;
   - a new editor-session file;
   - architecture history/revision storage.
