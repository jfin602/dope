IMPLEMENT

1. Generalize targeted refinement basis cleanly.

   Support targeted refinement from:
   - existing pending review basis;
   - initialized canonical Architecture edit basis.

   The accepted basis must include enough explicit identity to guard:
   - current canonical architecture fingerprint;
   - target System/Subsystem;
   - parent context when applicable;
   - current edited branch;
   - branch fingerprint.

   Do not make a canonical edit pretend it has a `reviewId`.

   Prefer a discriminated refinement basis or a thin canonical adapter around the existing `planTargetedRefinement` / `parseTargetedRefinement` pipeline.

2. Collect fresh deterministic evidence per accepted Search Deeper call.

   For initialized editing:
   - collect a fresh `ArchitectureEvidencePacket` at explicit call start;
   - pin it for that request;
   - select bounded branch-relevant evidence with the existing planner;
   - preserve packet/evidence provenance in the preview result;
   - do not persist the packet as review work.

   Keep existing pending-review behavior pinned to its existing review packet.

3. Guard canonical basis during the provider call.

   Before publishing an accepted refinement result, verify the canonical architecture fingerprint still matches the basis captured when the request started.

   If it changed, reject the result.

   The controller must separately reject the result if the current edited branch fingerprint changed while the request ran.

4. Reuse provider readiness/configuration.

   Search Deeper from initialized Edit Architecture needs an explicit way to make a synthesis provider ready after initialization.

   Reuse the current Local/Gemini:
   - configuration state;
   - model discovery;
   - selected model;
   - readiness/probe behavior;
   - secret handling;
   - no-silent-fallback rule.

   Expose only the bounded provider setup/status needed for Search Deeper from the Edit Architecture context.

   Do not duplicate a full onboarding workflow if a small reusable provider configuration component/helper is sufficient.

5. Preserve project-evidence safety.

   Do not send project evidence before the existing provider path considers the selected provider/model ready.

   Keep credentials out of project state and logs.

   Do not weaken existing warm-up/probe/readiness rules merely because the project is already initialized.

6. Accepted Search Deeper behavior.

   For System/Subsystem only:
   - starts from current edited branch, including manual edits;
   - preview says current draft unchanged;
   - preview shows proposed replacement and source-backed evidence;
   - source/document navigation works from the request's evidence packet where available;
   - Reject leaves draft unchanged;
   - Accept Refinement replaces only target branch in editor draft;
   - unrelated branches/manual edits remain;
   - dependency constraints outside the replaced branch remain;
   - canonical architecture/marker remain unchanged.

7. Save remains separate.

   After Accept Refinement, only explicit Save Architecture may invoke the P1 canonical write.

   Search Deeper/Accept Refinement must never call Save automatically.

8. Async/project guards.

   Reject/ignore late results after:
   - workspace switch;
   - editor reload/discard;
   - canonical basis change;
   - target branch edit;
   - newer refinement request.

   Provider cancellation/supersession must not publish stale preview state.

9. Keep pending-review Search Deeper Green.

   Existing pending review:
   - uses pinned review packet;
   - preserves manual review edits;
   - previews first;
   - rejects stale branch;
   - accepts into review draft only.
