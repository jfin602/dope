## Event contract and behavior

The pinned Pi SDK's actual `message_update` / `thinking_delta` Work events are forwarded as ordered `reasoning` events. They are optional. A provider with no thinking deltas creates no reasoning record and does not wait for reasoning. The worker limits forwarding to 96 reasoning deltas of at most 2,000 characters each and emits one omission marker if that limit or a per-delta bound is crossed. The adapter buffers incomplete trailing words across deltas before redaction, then emits incremental sanitized text. It flushes before each non-reasoning SDK event and before the final answer, preserving the observable order. Provider-internal reasoning unavailable through this SDK event is not captured.

Each Dope Work tool callback emits a stable `pi-<call number>` identity and `requested`, `validating`, broker-dispatch/`executing` when evidenced, and terminal phase. `executing` is not assigned to parser rejection or broker denial. The terminal phase is `completed`, `failed`, `recoverable`, `denied`, or `cancelled`. A malformed read can return the R1/R2 corrective code to Pi and continue in the same run; a fatal authority error still stops the run. The callback's actual stage and broker status generate the diagnostic, not the final model answer. Exact known basis/identity/output errors have safe codes; otherwise an unexpected thrown broker failure is labelled `UNEXPECTED_RUNTIME_FAILURE` and fails closed. A broker returning only `denied` cannot disclose which internal check denied it; the transcript records `AUTHORITY_DENIED` without inventing a narrower cause.

Validated request summaries include read path/range/source-identity presence, list path/limit, edit path/operation/content byte count and SHA-256, approved command ID/kind, or output-read offset/limit. Unknown or malformed provider input contributes field names and argument type only. Result summaries retain range/end/continuation, source hash, count/truncation, command output identity, or safe output byte counts when actually returned. They do not retain file bodies, edit content, raw shell commands, grants, credentials, or continuation handles. An authorized file page still reaches Pi unchanged under the existing broker policy; History retains metadata only. The existing command record retains a bounded, sanitized first output excerpt without the opaque continuation handle. A saved excerpt is labelled sanitized and must not be treated as byte-exact source.

The final assistant response is taken from the actual completed Pi message, sanitized and retained separately to a 12,000-character adapter ceiling and 12,000-byte transcript ceiling. Its truncation flag remains true if Pi's 65,536-character worker ceiling or the adapter ceiling was crossed. Failed or cancelled turns do not gain a completed final answer from partial model text. The existing transcript's 2,000-record and 8 MiB limits mark incomplete persistence rather than silently claiming a complete record. Recording exceptions interrupt and fail the active run through the existing AgentRun path. Presentation callbacks are not awaited by Pi; there is no UI animation or extra inference call in this scope.
