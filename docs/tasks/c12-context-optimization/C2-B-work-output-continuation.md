`read_file({path,maxBytes,offset,expectedSourceHash})` returns JSON with `path`, actual `offset`/`endOffset`, `nextOffset`, `fileBytes`, exact `text`, `truncated`, and `sourceHash`. Byte offsets and lengths are UTF-8; a requested page is at most 4,096 bytes. A continuation after offset zero requires the previous source hash. EOF has `nextOffset: null`, `truncated: false`; a read exactly at EOF returns empty text. The identity binds the Work run's candidate, project/root, path, complete file digest and candidate fingerprint. Any candidate content change invalidates it. The sandbox opens every component without following symlinks, reads from a verified file descriptor, checks UTF-8 boundaries, and rechecks the candidate before delivery. Protected paths and files matching the disclosure scan are denied as whole pages; altered source is never described as exact.

An approved `run_command` returns its actual completed/failed status and JSON containing a bounded sanitized excerpt, `outputIdentity`, opaque `handle`, byte range, `nextOffset`, `outputBytes`, and `captureTruncated`. `read_command_output({handle,offset,maxBytes})` returns later pages of that already completed result, up to 4,096 UTF-8 bytes per call. It cannot execute a command. Full captured output is sanitized before any page is cut, so secrets crossing page boundaries are removed consistently. Diagnostic newlines and safe stack text remain. The handle is scoped to the active adapter/Work run and its candidate fingerprint, originating approved command kind and grant; every retrieval repeats run, model, grant, workspace, cancellation and source-basis checks. A revoked, foreign, expired or ended run cannot retrieve it. The record keeps only the broker's existing bounded capture; a truncated capture drops its boundary bytes to avoid disclosing a partial credential. Missing bytes remain unavailable and are reported by `captureTruncated`. A failed command stays failed, and its output never substitutes for Dope's authoritative validation.
