## Exact SDK findings

Pi checks its current session projection against `contextWindow - reserveTokens`. It uses provider-reported assistant usage when valid and its own character-based estimate when usage is missing or stale. The preparation's `tokensBefore` and the result's `estimatedTokensAfter` are **estimates** in these fixtures; they must not be called provider token measurements. At the loaded 16,384-token model window, Dope's existing reserve is 4,096 and recent retention is 2,048. Both settings remain unchanged.

Crucially, `AgentSession._compactBeforeNextAssistantResponse()` runs through `prepareNextTurnWithContext` **between tool turns**, before the next model request. This is the safe proactive Work path. The SDK also checks before a new prompt and after an agent run. It invokes `session_before_compact` with `reason`, `willRetry`, and a prepared cut. Returning no replacement lets Pi use its built-in `compact()`; returning `{ cancel: true }` prevents it. The default summarizer makes an additional request to the **same selected model**; a split turn can require two summary requests. It serializes prior user/assistant/tool text, truncates each old tool result to 2,000 characters for that request, omits reasoning blocks, merges a previous summary, and asks for goal, constraints, progress, decisions, next steps and critical context. It rejects error and length-stop summaries and tool calls. It does not prove that model-written content is correct.

Pi retains the recent tail from the cut point, never cuts at a tool result, and carries the current system message into the compaction entry. Dope's current-turn Chat systems, including protected `/roadmap` instructions, remain system messages. Chat still reconstructs and disposes a separate Pi session on each saved turn; no Chat history-selection change was made. After successful compaction, Pi refreshes its context projection and continues the pending tool run. The summary is a model note, not a source snapshot. `AgentSession.compact()` is a **manual** API that aborts the active operation, so C3-A does not call it during Work.

Pi's overflow recovery can omit the failed response, compact, and retry. That is unsafe when a tool effect may already have happened. Dope's hook still cancels every `willRetry` compaction, and the worker rejects that run. Native threshold compaction uses `willRetry: false` and does not replay a tool effect. SDK settings keep automatic request retry disabled in this worker.

## Change and preservation contract

Before C3-A, `compactExact()` only replaced byte-identical messages with references and rejected most unique histories. It returned a complete exact-content JSON payload as the summary. The new `beforeNativeCompaction()` is a narrow guard: it cancels overflow retry and otherwise lets the SDK summarize unique older content. The worker records only hashes of summarized input and resulting summary, Pi's before estimate, trigger, duration, summary byte size, optional after estimate, and optional reported summarization usage. Raw summary text and raw tool contents are not sent to Work History or diagnostic logs.

The worker's system instruction now tells Pi to treat compaction summaries as unverified notes, distinguish verified tool results from interpretations and plans, and recheck exact source and effects through Dope. Native summaries can still omit or misstate facts; the deterministic fixtures use controlled summary text and establish lifecycle behavior, **not live model summary quality**. C2 ranged reads and command-output paging remain available for re-verification. The active user request and current system instructions are retained by Pi's cut/projection rules; recent open tool context stays in the retained tail. Completed, failed and denied results remain distinguishable in Dope's authoritative transcript/broker records, independent of a summary's wording.

No grant, task ID, project root, model selection, candidate fingerprint, approved command, tool inventory, source-hash check, human review, or canonical promotion rule changed. Work still runs the next tool through `PiWorkExecutionAdapter` and `LocalToolBroker`; Chat still uses its read/command broker. A summary cannot grant tools, approve a command, validate a test, or prove a file mutation. Cancellation, denied broker results, and overflow retries retain their existing stop behavior. The existing isolated resource loader still exposes only Dope's exact tool set.

## Work observability

The worker emits one bounded `compaction_succeeded` or `compaction_failed` Work lifecycle event when Pi ends a compaction. Host validation accepts only the stated trigger and nonnegative safe integer metrics. Work renders a factual **Context compacted** event with trigger, *estimated* before/after context, summary bytes, duration and provider-reported summarization tokens only when present. A failure is a warning. The existing Work event store persists this observation through reload; it stores neither the private summary nor tool bodies. Chat keeps its existing bounded compaction digest fields and canonical saved-context hash; those hashes are identities, not proof of semantic fidelity or tool effects. No reasoning-stream or visual layout change was made.

## Remaining C3-B and limits

C3-B must separately design safe continuation after uncertain interruption, with Dope-side candidate reinspection and no automatic replay of a potentially completed edit or command. C3-A does not provide that. Live C3-A qualification still needs one bounded observed compaction followed by useful authorized action and correct final evidence on the same source. A live model may write an incomplete or misleading summary, and the SDK's default summarizer does not label each statement by provenance; Dope therefore keeps summaries advisory and requires current broker/validation records for effects.
