## Presentation behavior

- Consecutive saved reasoning records form a collapsible **Reasoning** disclosure. Paragraphs are buffered across records; completed paragraphs and bounded chunks reveal with the Chat fade only for newly arriving text. Tool/final/marker boundaries flush the tail. Historical content appears immediately on reload. No reasoning records produce no reasoning disclosure or wait state. Truncation and omission markers remain visible.
- Tool lifecycle records correlate by stable `toolId` into one card at the first call position. The card updates its actual phase and exposes recorded request, execution, result and code fields. Missing metadata is labelled unavailable. Known fields are whitelisted; the R4-A grant revision field is not rendered. The command output excerpt is shown within its matching structured tool card when the `commandId` equals the tool ID; unmatched legacy commands retain their own disclosure. The generic event list remains for historical runs without a structured transcript and is not repeated above a structured one.
- A saved final message gets a horizontal divider, **Final result** heading and safe Markdown body. Reasoning and tool status are separate. Truncation is explicit. A run without a saved completed message gets no synthetic final answer; run, validation and review status remain separate.
- Existing backend `run`/`event`/`transcript` notifications now schedule a coalesced incremental cursor read. New entries append without rebuilding the transcript; existing tool nodes and expanded state stay in place. A terminal transition reconciles updated legacy command records once. The read is frontend-only and never awaited in Pi's execution callback. Project switch and widget disposal invalidate reads; no polling service was added.
- The existing follow state preserves the user's position when they scroll upward. The **Latest** control resumes following. Native details/summary elements supply Enter and Space disclosure behavior and selectable text. Focus indicators, narrow wrapping, bounded code scrolling and reduced-motion fade suppression use the existing theme/CSS rules.
